# 큰 작업 의도와 관측 기반 대상 선택

기본값은 TARGET_POLICY=observed. TARGET_POLICY=planner는 이전 좌표 지정 정책의 비교·복귀용이다. 액션 17종은 그대로 유지한다.

- LLM: 중기 작업 설명, 원하는 총 소지량(desiredInventory), 제약을 반환한다. 채굴 좌표·이동 목적지·순차 mine/move 단계는 받지 않는다.
- JEV: 시야 블록, 관측한 이동 후보, 보이는 드롭, 현재 가능한 해금 제작, 자기보호 중 action+parameters를 고른다. 같은 종류 블록과 방향이 후보를 독점하지 않도록 종류·방향별로 제한한다.
- 로컬 실행: 현재 시야/소지품/경로/실패 조건을 다시 검사한다. 목적지는 최근 경로가 확인된 후보여도 실행 성공을 보장하지 않는다.
- 복잡한 건축·보관·전달·장비는 기존 파라미터 제안을 유지한다. 후보일 뿐 자동 실행하지 않는다. 모든 액션의 파라미터를 JEV가 처음부터 생성하는 구조는 아니다.
- 총 소지량 조건이 충족되면 추가 채집 후보를 중단하고 다음 의도를 검토한다. 아무 목표도 없는 관측/대기와 명시적 의도의 작업을 구분한다.

## 기억과 사후 평가

food는 0~20의 음식 게이지이며 숫자가 클수록 가득 찬 상태다. food=5에서 즉시 먹지 않은 선택은 오답으로 채점하지 않는다.

경험은 구체적 실행 계획·결과·전후 상태와 판단에 사용한 가이드라인 ID/버전을 기록한다. 같은 세션의 이전 결정과 최대120초 이내의 후속 관측을 연결해, 나중에 먹었는지·게이지가 비었는지·체력 손실이 관측됐는지 제공한다. 관측되지 않은 미래와 인과관계는 확정하지 않는다. 후속 관측이 없는 경우 pending이며, LLM은 불확실성을 유지한다. 이후 결과를 검토할 때 앞선 경험도 다시 조회해 기존 가이드라인을 개정할 수 있다.

기존 건강·적 종류·장비 조건에 음식 게이지, 음식 보유, 소지품 조건을 추가했다. 현재 작업 관련성과 상황의 구체성을 기준으로 최대4개를 검색한다. 기존 기억은 마이그레이션 없이 읽으며, 새 필드는 선택 사항이다. 가이드라인은 근거 ID·반례·버전을 보존하고 현재 상황·실행 가능성보다 우선하지 않는다.

## 검증과 제한

304개 모의검증·타입 검사 통과. 큰 의도 입력 계약, 독립 대상 후보, 숨은/발밑 대상 제외, 재료 충족 후 중단, 시간차 식사 관측, 세션 분리, 기억의 개정·재접속 검색, 로그인 전 관측을 확인했다.

실제 시작 전 로그인 전 인벤토리 접근 오류를 발견했다. API 호출/서버 로그인 없이 종료됐음을 클라이언트·관리자 기록으로 확인한 후 고쳤다. 실패한 시도를 지우거나 성공 회차로 세지 않았다. 최종 관측 오류가 정산을 막지 않도록 테스트 하네스도 보강했다.

## 실제 2분 비교 (2026-10-18)

관리자가 같은 테스트 월드 기준점을 A/B로 복사해 파일 체크섬을 확인했다. 봇별 물자·배치·시간·날씨·난이도는 동일하고 각각 새 기억으로 시작했다. 세부 목표는 부여하지 않았다. 두 회차 모두 120초 제한으로 정상 종료했다. 자연 적대 몹 스폰은 꺼져 있었다.

두 봇의 시간 평균:

| 실행 상태 | 기존 planner | 새 observed |
|---|---:|---:|
| 실행 중 액션 없음 | 56.8% | 48.0% |
| 명시적 idle | 21.9% | 14.3% |
| look | 6.4% | 11.4% |
| 나머지 작업 실행 | 14.8% | 26.2% |
| 미관측 | 0.1% | 0.1% |

액션 없음+idle은 78.7% → 62.3%(약16.4%p 감소). activity_sample을 시간 적분했으며 모델 응답 대기와 겹친 시간을 원인별 독립 손실처럼 합산하지 않았다. 재현 집계는 scripts/pilot-report.ts, 정의는 src/activity-metrics.ts에 있다.

중기 LLM 계획 적용은 기존38회, 새42회였다. 큰 의도 형식으로 바뀌었어도 재검토 호출 빈도까지 줄어든 것은 아니다. 재검토 사유/목표 진전의 연결은 후속 과제다.

기존 회차: 작업 성공19건, 작업 실패3건, 제작/채집 중심. 새 회차: 작업 성공50건(이동41회, 제작3회, 작업대 설치4회, 채굴2회), 작업 실패0건, 탐색 중심. 새 회차의 채굴은 작업대와 잔디였으며 자원 채굴 효율 개선을 입증하지 않는다. 클라이언트의 파괴/획득 기록과 관리자 최종 블록/인벤토리를 대조했다. 서버의 드문 샘플만으로 작업대 회수 순간을 독립 확인한 것은 아니다.

새 회차에서 판자12개를 소비해 작업대3개가 월드에 남았다. 설치4회와 작업대 파괴1회가 기록돼 반복 낭비 가능성이 있다. 목적지 선택의 자율성과 실행 시간 증가는 확인했지만 유용한 생산성·협동 개선을 주장하지 않는다. 두 봇 모두 체력/음식 게이지20을 유지해 식사 지연의 실제 생존 영향은 이 회차로 평가하지 못한다.

새 회차에서 없는 액션 build 제안2건은 거절 후 재계획으로 회복했다. 이후 정확한 허용 액션 목록, place_table/place_block의 차이, 구체적인 오류 피드백을 보강했다. 이 후속 문구는 모의검증했으며 별도 게임 재실행은 하지 않았다.

## 실제 기억 검토 결과와 한계

실행 중 각 회차4번의 LLM 기억 검토가 있었지만 신규 가이드라인은0개였다. 이후 새 회차의 실제 경험을 끝까지 추가 검토하고 저장 파일을 다시 열어 JEV에 기록 상태를 재생했다(게임 재접속/행동 없음). 대상 기록 재검토2회도 진행했으나 신규 지침은 여전히0개였다. LLM은 이동 성공만으로 탐색 목표에 기여했다고 판단할 수 없고, 짧은 기록으로 재사용할 지침의 근거가 부족하다는 취지의 이유를 반환했다.

따라서 실제 경험 저장·LLM 검토·무갱신 처리·JEV 재생 호출은 확인했지만, 새로 학습한 지침의 실제 행동 개선은 미검증이다. 지침의 생성/개정/반례 보존/조건 검색/재접속/입력 전달은 모의검증했다. 지침 수를 늘리기 위해 규칙이나 경험을 주입하지 않았다. 검토에는 동작 성공과 목표 기여의 차이를 명시하고, 무갱신 이유도 진단 로그에 남기도록 했다.

비용(usage와 설정 단가 기준): 기존 회차 $0.251108106, 새 회차 $0.196738558, 후속 기록 검토/JEV 재생 $0.009854984, 목표 기여 재검토 $0.0033222. 합계 약 **$0.4610**. 로그인 전 실패 시도는 모델 호출0회였다.

이 비교는 자율 목표가 서로 달랐던 한 쌍의 짧은 기능검증이다. 최신 후속 프롬프트 보강 이전 코드의 실제 수치이며, 반복 비교·다양한 환경·학습 효과에 대한 통계적 결론이 아니다. 본실험은 실행하지 않았고 종료 후 봇은 미접속이다.
