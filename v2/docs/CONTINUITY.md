## 실패한 접근도 기록

- wait 이름과 stop 설명만 바꾼 첫 실제 검증은 중단 선택이 반복되어 조기 종료했다.
- 유지/중단 질문 분리만으로도 취소가 완전히 해결되지 않았다. 동일 작업 정규화와 연속 확인을 추가했다.
- 다음 검증에서 계획 밖 제작과 무관한 이동 후보가 드러났다. 실행률 증가만으로 유용한 진전이라고 판단하지 않았다.
- 짧은 회차에서 중기 모델 형식 오류와 관측 경로 실패를 발견했다. 실패를 성공으로 바꾸거나 안전장치를 풀지 않고 후속 수정 대상으로 남겼다.

## 검증 해석

`work`는 실행기가 작동한 시간이며 성공률이 아니다. `no_action`, 의도적 idle, look를 각각 기록한다. 새 블록을 보거나 이동한 것 역시 관측 진전일 뿐 자원 확보·협동 성과를 보장하지 않는다. 자연 스폰 OFF·초기 음식 제공 조건이므로 일반 야생 생존 검증으로 확장해서 주장하지 않는다.

## 후속으로 드러난 실행·목표 문제

- 재료가 충분하면 모든 목표를 없애는 응답이 나왔다. 자율 플레이는 유한한 수집 과제가 아님을 명시하고, 완료 뒤 다음 의도를 자유롭게 검토하도록 했다. 특정 건축물·직업·자원 순서를 강제하지 않는다. 기다림은 허용하되 재개 조건을 설명하게 한다.
- 설치 지원면이7종으로 제한돼 다른 일반 재료·잎에서 작업대가 후보화되지 않을 수 있었다. 일반 재료와 잎으로 확장하고 실제 충돌·공간·엔티티 검사와 시야 검사를 유지했다.
- 기본 look가 수평만 회전했다. 이제 명시적 각도가 없으면 수평/아래쪽을 번갈아 관찰한다. 감독 루프에도 최소2초 look 간격을 적용했다.
- 선택적 look에 `{}`를 반환하는 경우는 문서화된 기본 관찰로 해석한다. 부분적으로 빠진 각도나 범위를 벗어난 값까지 허용하지 않는다.

- 제작 실패는 부족한 재료 수량을 기준으로 제한한다. 수거/이동 경로 실패는 마지막 실패 위치에서1블록 이상 재위치해야 재시도가 가능하다. 시야·슬롯·다른 아이템 변경은 해당 조건이 개선됐다는 증거가 아니다.
- 실제529 응답 한 건은 재시도 후 회복했다. 해당 요청 사용량은 확인되지 않아 요청 상한으로 보수 계상하며 청구액으로 단정하지 않는다.

### 관측 기반 이동 입력

C9는 돌 곡괭이 제작까지 진행했지만 후반에 탐색 의도만 세우고 머물러 봇별 무진전 보호 종료했다. 임의 이동 후보 제거만으로는 모델이 복잡한 블록 목록에서 이동 지점을 고르기 어려웠다. 이제 `navigationTargets`는 직접 관측한 가까운 블록 지점 중 로컬 경로 탐색이 성공한 최대4개를 입력으로 준다. 새 목적지를 강제로 선택하지 않으며, 계획이 기존 move로 선택해야 실행한다.

2초 캐시, 최대8개 경로 검사·방향별2개 제한을 둔다. 차원 전환/재접속에서 캐시를 비우고, 실행 시 목적지 관측과 경로를 다시 검증한다. 보이지 않은 맵이나 장애물 너머의 자원 목록을 제공하지 않는다. 이동은 자동 채굴·기둥 쌓기·파쿠르를 하지 않는다는 능력 제한도 계획에 명시한다.

- 모델용 장소 요약과 실행 가능 여부는 다른 계약이다. 전체 관측 셀의 내부 인덱스로 목적지를 검증하고, 그 인덱스는 생성 모델/JEV에 보내지 않는다. 요약에서 빠졌다는 이유로 관측한 목적지를 거절하지 않는다. 실행 시 실제 경로 확인은 유지한다.
- 일시적인 API 과부하는1회 재시도 뒤 제공자별2~30초 대기로 전환한다. 대기 중 새 요청은 전송하지 않으며 성공하면 해제한다. 상한으로 이미 계상한 일시 오류 횟수만으로 종료하지 않고, 실제 금액·호출 수·미정산 사용량·응답 구조 오류를 구분한다.

- 후보 경로 조회가 실행 중 goto와 공유 A* context를 바꾸는 문제가 드러났다. 독립 탐색 generator와 별도 Movements를 쓰고 slice8ms로 제한했다. `getPathTo`를 단순한 읽기 전용 함수라고 가정한 것이 잘못이었다.
