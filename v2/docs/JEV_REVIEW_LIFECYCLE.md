# 행동과 계획 검토의 분리 — MC-056 후속

2026-10-18. 짧은 기능검증이며 본실험이 아니다. JEV가 행동과 인자를 선택하고, 로컬 코드는 물리 조건·실행 소유권·요청 수명만 관리한다.

## 확인한 원인

이전 120초 기록에서 재계획 선택 117건은 모두 최신 중기 계획을 받았다. 계획 나이 중앙값은 2.445초였고 107건은 5초 미만이었다. 계획이 전혀 도착하지 않은 문제가 아니다. 반면 피드백은 최대 60.153초 전 기록이 현재 장애처럼 남아 있었다.

동일 관측의 검토 요청이 이미 처리 중이어도 다시 큐에 남고, 새 계획 적용 뒤 다시 호출되는 회귀를 모의 실행으로 재현했다. 중기 의도에는 내부 호환용 `preferred: look`도 섞였다. 실제 `look` 43회 모두 직전 입력과 1도 미만 차이였지만 결과는 일반 성공으로만 남았다. Bob은 설치된 판자에 가려 한 블록만 보던 상태여서 환경 제약도 함께 작용했다. 모델 내부 이유를 단정하지 않는다.

## 변경

- `JEV_ARGUMENT_CONTRACT=coordinated`: 게임 행동과 배경 계획 검토를 별도로 선택한다. 대기·인자 철회는 가능하고 대체 행동을 강제하지 않는다. 이전 계약은 비교용으로 남긴다.
- 검토 요청 ID, 계획/관측/피드백 버전, 진행·완료 상태를 전달한다. 처리 중 같은 근거의 요청만 중복 제거하고 새로운 사실이나 실패는 보존한다.
- 검토 입력에 실제 포함된 실패만 검토됨으로 표시한다. 이후 생긴 실패를 지우거나 물리적으로 해결됐다고 표시하지 않는다.
- 모델이 선택하지 않은 호환용 `preferred: look`을 새 계약의 입력에서 제거한다. 실제 실행 계획과 기록은 유지한다.
- 각도 선택에 회전량을 명시하고 실행 기록에 카메라 전후·시야 진입/이탈 블록 수를 남긴다. 같은 방향과 회전량 0도 선택할 수 있다. 시야 진입은 최초 발견과 다르다.
- 결정 오류를 HTTP 상태·대기·전송·예산 등으로 분류한다. 키·요청 본문·서버 주소를 오류 메시지에 복사하지 않는다.

## 중간 실행에서 추가로 찾은 결함

첫 실행은 39.109초에 운영자가 중단했다. 이동 11회는 있었지만 두 번의 look은 여전히 방향 변화가 없었다. 약 20초부터 이동 인자 요청 30건이 토큰 한도를 넘었다. 기억한 이동 좌표가 629개로 늘어 질문과 누적 피드백이 커졌다. 첫 16초 오류 0건만으로 성공을 선언하지 않는다. 비용은 $0.1565069이다.

독립 검토에서는 장소 근거 ID가 관측 시각을 포함해 같은 장소도 새 관측으로 오인하는 버그를 찾았다. 실제 장소 근거 생성기를 사용한 회귀 검증을 추가하고 **내부 비교에서만** 시간 기반 ID를 정규화했다. 모델에 주는 원본 근거 ID와 세계 사실은 보존한다.

입력 크기는 전체 값의 표 표현·직렬화로 줄인다. 중요 좌표나 선택지를 버리는 방식은 사용하지 않는다. 이 방식이 미래의 무제한 기억을 수용한다는 뜻은 아니다.

## 평가 기준

행동 기록의 시작/종료 구간 합집합으로 실행 없음, 명시적 idle, look, 그 외 실행을 구분한다. 실패한 작업도 실행 시간에는 포함하므로 결과와 소지품 변화를 별도로 본다. 계획 호출 중 행동이 진행됐는지도 확인한다.

이전 문서의 활동 샘플 평균 98.78%는 원본에서 그대로 재현되지 않았다. 이번 비교의 기준은 실행 구간으로 다시 계산한 이전 무실행 98.3385%, look/idle까지 제외한 비작업 98.7460%다. 과거 값을 조용히 교체하지 않고 집계 기준 차이를 기록한다.

모델 입력190건의 작업 의도에서 합성 preferred가 제거됐고, 동일 근거 검토 요청8건이 중복 처리되지 않았다. 중기 계획39개가 적용됐다(이전41개). 중복 제거8건이 전체 계획 호출량을 크게 줄인 것은 아니다. 행동과 검토의 병렬 연결은 유지됐다. 과거 실패와 새로운 철회는 상태/버전으로 구분해 기록한다.

남은 미완결은123건: 목적지 철회120, 설치 아이템 철회2, 시선 철회1이다. 도착 반경 내 좌표로 실행을 거절한49건도 남았다. 이 중33건은 입력 때 이미 도착 반경 안이었고16건은 판단 중 진행하던 이동이 도착해 최신 상태 검증이 올바르게 거절한 경우다. look15회 중13회는 실제 회전·시야 변화가 모두0이었다. 나머지2회는 약0.45도 회전했고 시야에 각각3개·4개 블록이 들어왔다. 모두 직전 방향과1도 미만 차이이며 최초 발견이나 목표 진전으로 단정하지 않는다. 현재 방향을 알리고 결과를 기록해도 모델 선택 품질이 자동으로 해결되지는 않았다.

## 입력 크기와 비용

I의 초과 요청30개를 모두 재구성해 기존 바이트 수와 대조했고, 새 표 표현을 JSON 전송 후 복원했을 때 모든 사실과 질문이 일치했다.629좌표·33선택지를 유지하면서64,996–71,021바이트를50,416–57,349바이트로 줄였다. 그중3건의 실제 API 재생도 정상 응답했다. 그룹 선택 성공은 최종 인자 유용성의 증거와 다르다.

J에서 JEV605건·LLM72건 모두 정상 응답했고 HTTP/토큰 초과/decision_error는0건이었다. JEV 응답 중앙값270ms·p95 374ms, LLM 평균2730ms였다.

## 검증 범위와 다음 단계

타입 검사·374개 모의검증 통과. 실제 장소 근거의 시간 갱신, 요청/응답 교차, 새 실패 보존, 피드백 상태, 카메라 결과, 원래 값과 선택지의 복원, 구형 계약 유지 등을 검증했다. 추가로 표 인코딩의1000개 생성 입력 왕복 검사를 수행했다.

기본 계약은 legacy로 유지하고 이번 수정 계약은 coordinated로 명시해 실행했다. 로컬 강제 행동·임의 목표·중요 지도 삭제는 없다. 같은 초기 조건이라도 의도와 경로가 달라졌고 여러 수정을 묶은 단일 회차이므로 각 변경의 인과 효과나 일반 성능은 확정할 수 없다.

다음 핵심은 **유효한 이동 값을 충분히 보고도 철회하거나 이미 도착한 좌표를 고르는 판단**이다. 선택지 분할·철회 질문의 위치·입력 표현과 모델 판단을 같은 관측에서 비교해야 한다. 대기/철회를 없애 실제 개선으로 포장하지 않는다. 큰 지도에 대한 정보 접근 구조와 의미 있는 작업/협동 평가도 남아 있다. 현재 봇은 종료했고 추가 실행은 시작하지 않았다.
