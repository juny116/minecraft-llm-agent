# 행동·인자 분리와 완성 조합 비교

2026-10-18 · MC-056. 서버 실행 없이 저장된 관측으로 실제 JEV API를 호출했다. 운영 기본 정책은 바꾸지 않았다.

## 먼저 정정: 이전 재생의 이동 검증

모델 입력 로그는 실행기용 `observedDestinationKeys`를 의도적으로 생략한다. 이를 실행기 스냅샷인 것처럼 검증하면서 **보였던 좌표를 모르는 좌표로 잘못 거절**했다. 이는 평가 도구의 오류이며 모델 입력에 숨겨진 지도를 추가해야 한다는 뜻이 아니다.

이번에는 해당 관측의 `vision.blocks` 좌표만 검증용 인덱스로 복원했다. 원본 입력·응답은 그대로 보존했고 API를 재호출하지 않았다. 경로 가능성이나 보이지 않았던 과거 장소를 추정하지 않는다. [복원 도구](../scripts/replay-validation.ts)와 회귀 테스트를 추가했다.

이전 비교의 행동 고정 B 조건은 검증 통과 **12/18 → 18/18**, 행동부터 선택한 B는 **6/12 → 9/12**로 정정된다. “이동이 모두 이미 도착한 좌표라 실패했다”는 이전 해석은 철회한다. C 최종 확인 조건에는 잘못된 검사 결과를 이미 전달했으므로 단순 재집계로 비교를 복구할 수 없다. C가 효과 없다는 결론도 보류한다. [정정된 이전 기록](JEV_CHOICE_COMPARISON.md)

## 이번 비교의 계약

- **단계별:** 가능한 행동·인자 조합을 보여주고 행동을 선택한다. 이후 앞선 행동·이미 고른 인자를 명시하며 다음 인자를 묻는다. 인자 `none` 대신 명시적인 `revise`로 행동 선택으로 돌아갈 수 있다.
- **완성 조합:** 같은 행동·인자 조합 전체를 하나씩 제시하고 한 번에 선택한다.
- 둘 다 행동 단계의 대기·계획 재검토·선택 철회를 허용한다. 철회 시 로컬 대체 행동이나 무한 재시도는 없다.
- 관측·목표·기억은 동일하며 값을 좋고 나쁨에 따라 정렬하지 않는다. 조합 선택은 실행 성공의 보장이 아니다.

비교 범위는 실패 기록의 이동/설치 인자 요청 각 처음과75% 지점, 총4관측이다. 각 관측에서 이동·일반 블록 설치만 제공했다. 이동 좌표는 원래 도메인에서 좌표 해시 순으로12개를 추출했고, 설치는 관측된 아이템×위치 조합을 모두 제공했다. 총72~144조합이다. **이 작은 진단에서는 다른 액션과 나머지 이동 좌표를 제외했다. 운영 도메인을 줄인 변경이 아니며 전체 시스템 성능으로 일반화하지 않는다.**

두 조건에 정확히 같은 조합을 제공하고 각3회 반복, 순서를 교차했다. 단계별 인자 질문도 전체 가능 조합을 참조할 수 있다. 중요한 관측을 삭제하지 않고, 동일 조합이 질문과 상태에 중복되던 표현만 제거했다.

단계별 통과6건은 이동 한 관측3회와 설치 한 관측3회다. 나머지 선택3건은 실제 도착 반경 안의 좌표였고, 다른 관측3회에서는 선택을 철회했다. 완성 조합은 유효 이동2회·설치1회였으며 대기/철회가 많았다. 대기나 철회가 오답이라는 독립 정답은 없다.

**완성 조합이 더 일관되게 실행을 선택한다는 근거는 얻지 못했다.** 그러나 서로 다른4관측의 반복이므로 일반적인 JEV 능력 순위도 아니다. 목적 기여·실제 경로·설치 성공·실제 idle는 측정하지 않았다.

## 오류·비용·검증

- 첫 표현은 완성 조합 요청에서 HTTP400을 받았다. 동일 요청1회 진단으로 `max_tokens_exceeded`를 확인했다. 상태와 질문에서 중복된 조합 표현을 제거한 뒤 두 조건 전체를 새로 비교했다. 실패 시도와 수정 후 결과를 섞지 않는다.
- 초기 시도 비용 $0.008043714, 오류 확인 $0, 완료 비교 $0.029747214. 합계 **$0.037790928**, 모두 JEV. LLM·서버 호출 없음.
- 완료 비교39 API 요청, 오류0. 초기 시도에는 정상 응답과 거절 요청이 포함되며 모두 원장에 보존했다.
- 타입 검사와343개 모의검증 통과. 새 테스트는 저신뢰도 유효 선택, 선택 철회, 조합 보존, 잘못된 응답 거절, 검증용 가시 좌표 복원을 다룬다. 테스트 작성 중 누락한 관측 시각 필드를 보완했다.
- 재생 원본·질문·응답·각 호출 비용·실패 버전·재집계는 비공개 보존한다. 공개 도구: [선택 계약](../scripts/choice-contract.ts), [회귀 테스트](../test/choice-contract.test.ts).

## 판단과 다음 단계

이전보다 **입출력 계약과 평가 도구 문제의 비중이 명확해졌다.** 인자 none 제거 조건은 기존 보고보다 잘 작동했다. 동시에 명시적인 철회 선택을 남기면 철회가 다시 나오므로 이름만 바꾸는 것이 해결책은 아니다.

우선 단계별 선택 방향을 유지한다. 전체 조합 열거는 조합 수와 토큰 비용이 커지고 이번 비교에서 이점도 없었다. 운영 통합 전에는 명시적 철회가 필요한 사례와 단순 무진전을 구분하고, 가시 좌표 검증이 실제 실행기와 일치하는지 확인해야 한다. 이후 짧은 실제 기능검증에서 선택→실행→상태 변화→공백을 이어 측정한다. 이번 재생만으로 idle 개선 또는 본실험 준비 완료를 선언하지 않는다.
