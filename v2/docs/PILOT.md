# 5분 생존 파일럿 — 준비안, 미실행

목적: 장기 생존 점수보다 자기 목표의 생성·유지·보류·실패 대응과 협력을 관찰합니다. 세부 목표·직업·수집량·제작 순서는 지정하지 않습니다. 두 봇에 공통 GAME_CONTEXT만 주고 userRequest는 null로 시작합니다.

## 시작 전
- 새 목표 JSON 계약을 짧은 유료 smoke check로 먼저 확인. 현재 검증은 모의 응답까지이며 실제 모델 준수는 미확인.
- 개인 서버의 작은 일반 지형, 나무·접근 가능한 자원, 소량의 시작 음식. 기존 평지 fixture와 별도 namespace 사용.
- 처음에는 적대 위협 제한. 현재 스킬로 식량 자급/거친 지형/다양한 적 생존이 보장되지 않음.
- 동일 이름의 봇 중복 접속 금지. 시작 인벤토리·환경 조건을 기록하고 관리자 설정은 모델에 숨은 지식으로 주지 않음.
- 출력 토큰 여유, 실행당 최대300초·공유 호출/비용 한도, 기존 누적 비용 ledger 연결 확인. 일반 CLI만 실행하면 누적 ledger는 자동 적용되지 않음.

## 종료 조건
5분·설정한 비용/호출 한도·사망·심각한 체력 저하·계속되는 무진행/오류 중 먼저 발생한 시점. 기록을 보존하고 봇 접속 종료. 자동 재시도·재시작으로 시간을 연장하지 않습니다. 준비된 scripts/survival-pilot.ts는 최대300초·300호출·실행당 추정0.25달러(설정이 더 작으면 그 값)를 제한하고 기존 누적 ledger를 사용합니다. 체력6 이하, 사망/접속 종료, 봇별4회 실패/부분 결과, 2분간 유의미한 성공 행동 또는 전송된 대화 없음에 종료합니다. 마지막 조건은 진행의 간단한 운영 지표이며 학습/탐색의 가치를 판정하는 척도가 아닙니다. 종료 시 미정산 API 예약이 남으면 ledger를 미확인 상태로 보존하고 다음 실행을 막습니다.

## 관찰 항목
- 목표의 관측 근거, 불필요한 목표 변경과 중복 목표
- 보류한 일을 기억하고 적절히 재개하는지
- 실패 후 방법 변경·도움 요청, 완료 작업 반복 여부
- 대화/약속과 실제 행동의 일치, 상대 보고와 직접 관측 구분
- 행동별 시간·실패·API 비용과 과도한 대기

승인된 실행 시 v2/에서 다음과 같이 시작할 수 있습니다. 아래 명령은 실제 서버·API를 사용하므로 준비/승인 전에 실행하지 않습니다.

```bash
MEMORY_NAMESPACE=survival-pilot-v1 RUN_SECONDS=300 LLM_MAX_OUTPUT_TOKENS=1536 node --import tsx scripts/survival-pilot.ts --live-functional --with-api
```

먼저 RUN_SECONDS=30으로 새 목표 응답 계약을 확인하고 결과를 검토합니다. 시간은 접속 준비 후부터 측정하며 연결 대기는 최대20초입니다.

현재: 목표 구조·실행기·종료 조건 모의검증 완료. 새 구조의 실 API와 서버 조건 확인 후 진행. 5분 실행이나 본실험은 아직 시작하지 않았습니다.
