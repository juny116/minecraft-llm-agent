# 이동 선택 뒤 목적지 철회: 입력 계약과 순서 비교

2026-10-18 · MC-056. **전체 목록을 유지한 저장 입력에서, 구체적 좌표 제안 뒤 철회를 묻는 순서가 일부 사례를 개선했다.** 실제 이동/공백 개선이나 일반 생존 능력은 아직 검증하지 않았다. 서버 재접속·본실험 없음.

## 먼저 바로잡은 검증 한계

지난 look 재생은 `observation`에서 상태를 복원했지만 모델 observation은 실행기의 과거 `places`를 포함하지 않는다. 다른 행동인 move로 바뀌면 목적지 목록이 일부만 복원됐다. 당시8/36개 같은 제한 도메인의 이동 완료·철회 결과를 실제 전체 목록의 성능으로 해석할 수 없다.349입력의 직전 look 결과/현재 시야 전달 감사는 이 문제와 독립적으로 유효하다. 기존 원본과 비용을 보존하고 [당시 보고서](LOOK_FEEDBACK.md)에 정정을 추가했다. 구형 도구는 부분 도메인 진단임을 명시하는 플래그 없이는 실행되지 않는다.

새 재생은 실제 서버 `bindingDomain`의 첫/root 목적지 질문에서 **전부** 복원한다. 각 봇의 철회 중간/마지막과 bind 대조 사례를 사용한6관측, 각 조건2반복이다. 도메인은107~582개이며 순서와 계층 분할을 유지했다. move 행동은 이미 선택된 조건으로 고정한다. 서로 다른 봇의 입력이나 이후의 관측을 섞지 않는다. 작은 실패 편향 표본으로 일반 성능을 추정하지 않는다.

## 확인한 구조와 수정

실행기는 좌표 칸 자체에 서는 것이 아니라 `GoalNear(...,2)`로 접근한다. 그런데 질문은 좌표와 경로 불확실성을 주로 설명했고, 과거 관측 블록의 종류·시각은 좌표 도메인과 직접 연결되지 않았다. 이를 보완했다.

- move의 반경2 접근, 실행 시 경로 확인, 이미 반경 안이면 이동하지 않는 의미를 명시한다. 이동 성공을 보장하거나 불확실성을 지우지 않는다.
- 실제로 본 블록의 이름·좌표·관측 시각·현재/과거 구분과 기존 navigation hints를 연결한다. 힌트의 과거 국소 경로 확인은 현재 경로 보장과 구분한다. 미관측 지형을 추론하지 않는다.
- 과거 블록을 장황하게 추가한 진단에서 context_limit HTTP400이1회 발생했다. 블록 이름 사전과 좌표/시각 기준값+차이를 쓰는 무손실 표로 바꿨다. 좌표/블록/시간을 삭제하거나 중요한 후보를 잘라내지 않았다. 더 큰 지도에서 한도 초과가 완전히 해결됐다는 주장은 하지 않는다.
- 선택형 `JEV_WITHDRAWAL_MODE=proposal`: 그룹/좌표를 먼저 임시 제안하고 구체적인 값에 대해 bind/withdraw를 판단한다. 그룹 선택은 실행 승인이 아니며, 최종 철회 시 대체 행동 없이 unresolved다. 다른 인자도 같은 계약을 사용할 수 있지만 이번 API 비교는 destination만 검증했다. 기본joint와 기존separate를 유지한다.

전송용 factual context가 늘어나는 변화와 질문 순서 변화는 비교를 나누어 검증했다. 전체 행동·각도·좌표·철회 선택을 유지했다. 로컬 선호 점수·강제 행동·인자 대체는 추가하지 않았다.

## API 결과

모든 정상 비교는6관측×2반복/조건이며 조건 순서를 교차했다. 인자 선택 완료 후 도착 반경 밖인지 확인했다. 실제 경로 성공이나 유용한 진전으로 세지 않는다.

| 비교 | 조건 A: 반경 밖 선택 | 조건 B: 반경 밖 선택 |
|---|---:|---:|
| 기존 설명 → 접근 의미 설명 |5/12|4/12|
| 접근 설명 → 관측 근거 연결(무손실 표) |4/12|4/12|
| 같은 근거, 선행 gate → 임시 좌표 제안 후 최종 검토 |4/12|8/12|

최종 비교의 철회는8→4회, 호출24→36회, 전체 인자 판단 평균525→769ms였다. 성공하던 대조 관측2개는 유지됐다. Bob의 철회 관측2개가 각2반복 모두 반경 밖 좌표 선택으로 바뀌었고, Alice의2관측은 각2반복 모두 여전히 철회했다. 모든 선택 좌표는 원래 도메인에 있었다.

따라서 **구체적인 후보 없이 먼저 계속할지 묻는 순서가 일부 입력에서 선택을 막고 있었다는 증거**는 있다. 동작 설명이나 정보 부족을 주원인으로 확정할 근거는 없다. 나머지 철회가 적절한 신중함인지 모델 오류인지는 경로/목표 기여 검증 없이는 알 수 없고, JEV의 선택 확률을 내부 이유로 해석하지 않는다. 추가 호출의 지연이 실제 공백을 상쇄할지도 미측정이다.

중단된 장황한 관측 근거 비교는 접근5판단·근거4판단 후 입력 한도 오류로 끝났고, 완료 비교에 합치지 않았다. 비용은 모두 보존한다: 설명$0.026627916 + 중단$0.008818488 + 최종근거$0.027444984 + 순서$0.038186064 = **$0.101077452**, JEV만 사용. 최종 정상 비교들은 HTTP 오류 없이 완료했다.

## 검증·다음 단계

384개 모의검증과 타입 검사 통과. provider 경로에서 두 순서의 bind/withdraw, 저신뢰도 허용, 철회 시 selected 없음, 원래 값 유지, 과거/현재 블록과 표 복원을 확인했다. 재생 도구는 `scripts/move-context-replay.ts`; `--grounding`, `--proposal`로 분리 비교한다. 새 trace는 실제 준비된 context/questions를 함께 저장한다. raw 로그·비용·운영 정보는 비공개다.

다음은 proposal 모드의 짧은 실제 기능검증에서 물리 이동 성공·목적지 왕복·무실행 시간을 함께 확인하는 것이다. 같은 입력에서 선택 완료가 늘었다는 이유로 자율 동반 플레이 준비 완료나 본실험 진입을 선언하지 않는다. 실패한 가설과 평가 정정까지 포함해 개선 방향을 판단한다.
