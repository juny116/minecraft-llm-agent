# JEV의 구체적 대상 선택: 기능 탐색

2026-10-18 초기 탐색 기록. 이후 기본 구조는 [큰 작업 의도와 관측 대상 선택](WORK_INTENTS.md)으로 전환했다. 아래는 전환 전 기록이다.

현재 executionOptions는 LLM이 제안한 mine.expected와 같은 블록만 추가하며 이동 목적지도 LLM 제안에 의존한다. 큰 목표만 제공하면 mine/move 후보가 생기지 않는다. 이것은 JEV API의 제약이 아니라 후보 생성 정책이다.

## 작은 실제 API 검증

scripts/target-choice-probe.ts는 게임에 접속하지 않는다. 명시적인 --with-jev 실행에서만 비용을 사용하며 공용 기능검증 ledger에 기록한다. 실행 상한 $0.10 / 18호출이며 누적 승인액은 스크립트의 FunctionalLedger 인자를 운영자의 실제 승인에 맞춰야 한다. ledger를 초기화하거나 미정산 항목을 지우지 않는다.

관측된 나무/돌/흙 3개와 이동 위치 2개, 먹기 후보를 코드로 제공한다. 기존 candidates 검증을 재사용하지만 실제 도달 가능성이나 채굴 성공을 증명하지 않는다. 구체적 추천 plan은 전달하지 않는다. 6개의 수작업 상태에서 후보 순서를 3가지로 바꿨다. 정답 기준은 호출 전에 정의했다.

- 목재/조약돌/흙 목표에 따른 채굴 대상 선택: 9/9.
- 관측된 동료 위치에 따른 이동 목적지 선택: 6/6.
- 허기 5에서 채굴보다 식사 우선: 1/3. 나머지 2회는 나무를 선택했다.
- 총 16/18, JEV jev-1.14.0, 실제 사용량 기준 $0.001040634. LLM 호출 0.
- 왕복 시간 166~286ms. 작은 입력에서의 결과이며 운영 환경 지연으로 일반화하지 않는다.
- 기존 후보 생성기로 동일한 큰 목표만 넣으면 채굴 후보 0개.

단순하고 인위적인 소표본이며 후보 순서와 모델 변동의 영향을 분리하지 않았다. 다양한 목표, 장기 생존, 협동, 실제 경로 수행 능력을 검증한 것은 아니다. 위험 필터링 성공률을 모델 지능으로 계산하지 않았다.

## 당시 제안한 구조 — 후속 구현은 WORK_INTENTS.md

1. LLM은 의도, 완료 조건, 제약, 재검토 조건을 만든다. 예: 기본 도구용 재료 확보, 필요한 수량 확보 후 중단. 모든 블록 좌표를 지정하지 않는다.
2. 로컬 코드는 현재 시야의 블록, 관측한 이동 가능 위치, 현재 소지품/해금 제작법으로 후보를 만든다. 실패 이력과 현재 조건을 검사하고 종류·방향별 후보가 살아남도록 제한한다. 발밑 블록·숨은 정보는 제외한다.
3. JEV는 action+parameters 묶음의 ID를 고른다. 액션과 대상을 독립 질문으로 골라 서로 모순되게 만들지 않는다. 현재 행동 유지도 후보로 둔다.
4. 로컬 실행기가 접근·채굴·수거를 수행하고 재검증한다. 결과와 상태 변화는 기존 경험/목표 검토로 보낸다.

허기 반례 때문에 긴급 자기보호 판단과 일반 작업 선택을 분리해 시험할 필요가 있다. 같은 호출 안의 독립 질문으로 얻은 판단을 코드가 조합할 수 있지만 우선순위 계약과 반례 검증이 필요하다. confidence 하나로 행동을 막지 않는다.

다음 검증은 관측 기반 후보 생성기의 누락/과다 후보, 소지량 충족 후 중단, 실패 대상 회피, 행동 유지, 위험과 식사 우선의 충돌을 포함한다. 이후 기본 정책을 바꾸기 전에 짧은 실제 서버 비교에서 idle·실제 획득·이동 실패·비용을 함께 측정한다.

참고: [공식 Choice 문서](https://docs.typesafe.ai/primitives/choice), [독립 질문 평가](https://docs.typesafe.ai/introduction).

## 평가 정정

food=5에서 먹지 않았다는 이유로 실패라 부른 것은 부적절했다. 당시 식사 선택은1/3이었지만 나머지2회를 판단 오류로 확정할 수 없고 총16/18이라는 정답률도 생존 판단 평가로 사용하지 않는다. 현재 probe는 식사 선택에 pass:null을 반환하고 후속 결과가 필요함을 명시한다. 원본 실행 기록은 보존했다.
