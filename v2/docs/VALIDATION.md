## 최근 탐색 실험과 병목

두 봇에게 세부 목표를 주지 않은 탐색 실험을14분1초 수행했습니다. 같은 초기 월드·소지품, 낮·맑음 고정·자연 스폰 OFF 조건이며 위험한 야생 생존 실험은 아닙니다. 실행 중 코드 변경·개입은 없었고, 사전검증을 포함한 비용 상한으로 예정15분보다 일찍 종료했습니다.

서버 기록과 대조한 결과 채집·제작·설치·보관·전달은0건, 인벤토리는 그대로였습니다. 대화14건은 탐색·자원 위치 이야기였으며 실제 역할 분담이나 생산적인 협동은 확인되지 않았습니다. 중기 계획은 각각138회·109회 갱신됐지만 두 봇 모두 초기 탐색 목표를 완료하지 못했습니다. 장소 기록과 접근성 확인을 반복하는 것이 현재 주요 한계입니다.

전체 무실행 비율은 Alice68.8%, Bob59.9%였습니다. 이는 액션 실행 구간 외 시간이며 물리적 정지나 명시적 idle과 다릅니다. 표본상 무실행 대부분은 선택 요청 진행 중이었습니다. 개별 JEV 호출 중앙값은287ms, 전체 행동 판단은811ms였고 look 실행은44ms였습니다. 짧은 행동과 여러 단계의 선택 호출이 공백에 기여할 수 있지만, 호출 주기 단축만으로 해결된다고 단정하지 않습니다.

장소 근거 인용 오류12건, 작업 의도 형식 오류1건, 장기 목표 검증 오류2건, HTTP400 응답1건이 있었습니다. 잘못된 갱신은 거절했고 예산 종료 시 추가 요청도 차단했습니다. HTTP400의 상세 원인은 아직 확인되지 않았습니다.

별도120초 기능검증에서는 명시적 획득 요청 아래 JEV가 채굴을 유지해 석탄·조약돌을 각1개 얻고 목표 완료에 반영했습니다. 단계가 바뀐 뒤 도착한 전환 응답의 재판단은 모의검증했으며, 위 자율 실험에는 채굴이 없어 효과를 검증하지 못했습니다. 후속 수정으로 장소 기억 처리 결과를 각 판단 입력에 전달하고 관측 근거ID와 장소ID를 구분했습니다. 저장·무변경·일괄 거절·재접속 복원은 모의검증했습니다. 후속 두 봇3분 기능검증에서는 처리 결과가 중기·장기 LLM과 JEV 입력에 전달됐고, 한 봇이 약69초에 탐색 목표를 완료하고 새 조사 목표로 전환했습니다. 오류는0건이었지만 다른 봇은 기존 목표를 유지했고, 생산 활동은 없었습니다. 이전 실행의 첫3분 대비 평균 무실행 비율은53.1%에서43.4%였으나 단일 실행 비교로 개선 효과를 확정하지 않습니다. 접근 가능성을 확인하지 못해 보류를 반복하는 문제가 남아 있습니다. 이후 실행 규약·완료된 접근 증거를 보강한 두 봇3분 검증에서는 자율 채굴4회와 각 조약돌2개 획득, 상자 설치·판자14개 보관이 확인됐습니다. 결과에 따른 후속 추출 계획도 나왔지만, 평균 무실행 비율은56.5%로 이전보다 높았고 장기 목표 근거 오류1건이 있었습니다. 단일 실행으로 인과적 개선이나 접근 안전성을 입증하지 않습니다. 해당3분 로그를 분해하면 두 봇의 무실행 시간 합203.6초 중148.7초는 JEV API 대기였고, 그중35.2초는 대기 시간 인자 선택이었습니다. 명시적 idle 실행54.5초는 이 무실행 시간과 별도입니다. Bob의 선택 실패36건은 철회가 아닌 빈 상자·드롭 대상이었으며, 실패 후 다음 판단 전 공백은24.3초였습니다. 후속 수정은 연속 선택 경로의 wait/idle을 제거하고 stop을 취소 후 재판단으로 분리했습니다. 모의검증만 완료했으며 실제 공백 감소는 아직 검증하지 않았습니다. 다음 과제는 빈 인자 도메인의 명시적 전달, 실패 후 재판단 간격과 순차 호출 수, 기록 완료 후 계획 전환입니다.

저장된6개 look 입력을 방식별2회씩 실제 API로 재생했습니다. 조건부 세부 각도를 한 요청에 묶는2회 방식은 기존4회 대비 look 선택 중앙값1.035초→0.614초, 평균 비용 약21% 감소를 보였습니다. 두 방식의 행동 선택은12쌍 모두 같았고, 실제 look10쌍 중 각도는6쌍 일치했습니다. 명시적 세부 각도 진단은 양쪽6/6회 정확했습니다. 단순 구간+나머지 표현은 같은 진단2/6회로 실패해 채택하지 않았습니다. 모든1도 단위 각도는 유지하며 운영 기본값은 변경하지 않았습니다. 고정 입력 재생이므로 실제 시야·실행 공백 개선은 아직 검증되지 않았습니다. 비교 도구는 `scripts/look-binding-replay.ts`이며 `--with-api --input=로그경로 --parallel-branches`로 실행하고 `--angle-probes`로 별도 각도 진단을 수행합니다.

재생 도구는 `scripts/context-efficiency-check.ts`와 목적지 선택 비교 스크립트입니다. `scripts/guidebook-maintenance-check.ts`는 가상 경험의 실제 LLM 검증용입니다. 각 도구는 참조 복원과 해당 관측·선택 범위의 보존을 검사하며, 실제 API 호출은 `--with-api`와 비용 설정을 명시해야 합니다. 원본 로그와 운영 기록은 공개하지 않습니다.
