## 현재 병목

**현재 서버 결과.** 공통 `direct` 선택의 두 봇 기능검증은120초를 예정했지만 경로 실패 반복으로42.2초에 자동 종료됐습니다. 이동10회와 블록 설치8회가 성공했고 서버에서도 판자5개·원목3개 소모와 설치를 확인했습니다. 구조물은 봇 주변 통로를 좁혔으며 사용 가능한 거주지나 협동 성과로 평가하지 않습니다. 채집·제작·전달은 없었습니다.

**시야와 행동 공백.** 인자 철회는0건이었지만 `look`14회 중12회는 보이는 블록 집합이 그대로였습니다. 다른2회는 방향과 관측이 바뀌었고 다음 모델 입력 반영도 확인했습니다. 동일한 첫42.2초의 평균 무실행 비율은 이전33.1%→43.5%로 늘었습니다. 무실행은 액션 실행 구간 외 시간이며 물리적 정지나 명시적 `idle` 선택과 다릅니다. 승인 제거만으로 같은 방향 반복과 실행 실패가 해결되지는 않았습니다.

**입력과 선택 구조.** 현재 관측·중요 장소를 공유 참조로 전달하며 이번 실행의 입력 한도 오류는0건이었습니다. 계획 설명이 길이 제한을 넘어서1회 갱신이 거절됐습니다. 저장된 두 상황의 각3회 API 비교에서는 설명을 보강한 승인 방식과 `direct` 모두 다른 방향의 `look`을6/6회 선택했고 호출은6회→4회였습니다. 서버에서는 다른 실패가 드러났으므로 이 작은 재생 결과를 플레이 성능으로 일반화하지 않습니다. 경험 지침의 근거·반례 보존 병합은 확인했으나 장기 기억 품질은 미검증입니다.

다음 검증은 같은 방향 반복, 설치 후 통로와 실패 목적지의 재선택, 계획 갱신 실패의 회복에 집중합니다. 이전 버전의 장시간 실행 결과를 현재 선택 방식의 성능으로 합산하지 않으며, 다른 구현과의 통제된 성능 비교는 수행하지 않았습니다.

재생 도구는 `scripts/context-efficiency-check.ts`와 목적지 선택 비교 스크립트입니다. `scripts/guidebook-maintenance-check.ts`는 가상 경험의 실제 LLM 검증용입니다. 각 도구는 참조 복원과 해당 관측·선택 범위의 보존을 검사하며, 실제 API 호출은 `--with-api`와 비용 설정을 명시해야 합니다. 원본 로그와 운영 기록은 공개하지 않습니다.
