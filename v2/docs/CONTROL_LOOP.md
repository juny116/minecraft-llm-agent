# 판단·계획·대화·리스폰

액션은17종 그대로입니다. 유지/전환/대기는 실행 제어이며 새 게임 액션이 아닙니다. 회수는 목표/계획이며 이동·관찰·줍기 등 기존 액션으로 실행합니다.

| 역할 | 기본 주기 | 책임 |
|---|---|---|
| JEV 감독 |1초 목표, 한 요청만 진행 | 현재 실행 유지/전환, 구체적 관측 후보 선택, 메시지 수신 대상 분류 |
| 중기 LLM |45초 또는 계획 종료/실패/약속 변경 | 현재 목표 아래 작업 순서 제안; 직접 실행하지 않음 |
| 장기 LLM |180초 또는 재접속/리스폰/검토 요청 | 목표 근거·보류·완료 검토, 회수/준비/보류/포기 판단 |
| 기억 정리 |60초와 미검토 경험 조건 | 근거·반례 기반 가이드라인 갱신 |
| 대화 LLM | 처리할 메시지 또는30초 간격의 능동 발화 검토 | 응답·질문·제안·별명 기억 |

주기는 설정값이며 API 응답 지연 동안 같은 역할을 중복 호출하지 않습니다. LLM을 기다리는 동안 기존 실행과 JEV 판단은 이어집니다. JEV 응답은5초 신선도와 현재 조건을 확인하며, LLM 기본 응답 대기는120초입니다. JEV 요청 대기는 별도 JEV_TIMEOUT_MS(기본5초)입니다. 실행은 하나만 소유하고 전환 시 이전 실행의 취소 완료를 기다립니다. 같은 작업 유지에는 채굴/이동 재시작이 없습니다. 중요 변화는 다음 heartbeat 판단을 앞당기지만 호출 큐를 쌓지 않습니다.

## 대화와 별명
정확한 이름 매칭으로 수신자를 확정하지 않습니다. JEV가 본인 정체성·대화 맥락·참여자·별명 가설을 함께 보고 respond/clarify/observe/other/defer로 분류합니다. 이 분류는 행동 선택과 같은 요청에 포함됩니다. 애매하면 확인 질문을 할 수 있고, 명확히 다른 상대에게 한 말에는 응답하지 않습니다.

응답 대상 메시지는 큐에 남기고 LLM이 처리합니다. 생성 중 도착한 새 메시지는 다음 응답에 남습니다. 답변은 replyTo로 원문과 연결하며, 단순 행동 변화 때문에 질문 답변을 버리지는 않습니다. 진행 보고의 인벤토리/위치/현재 행동이 바뀌면 재검토합니다. 기존 발화 속도 제한을 유지합니다.

LLM은 실제 메시지에 등장한 별명만 근거 메시지 ID와 함께 저장할 수 있습니다. 별명에는 대상의 실제 계정명·소개한 화자·잠정/확인 판단·이유를 남깁니다. 확인은 모델 판단이지 인증된 신원 증명이 아닙니다. 서로 충돌하는 별명은 보존해 확인 질문에 활용하며, 새 별명 근거가 생기면 최근 애매한 메시지를 재분류할 수 있습니다. 별명과 채팅은 권한이나 시스템 지시가 아닙니다. 재접속해도 별명과 메시지 처리 상태가 유지됩니다.

## 사망과 회수
Mineflayer 자동 리스폰을 사용합니다. 사망 직전 관측한 위치·차원·소지품·주변 적·피격·물/용암 상태를 기록합니다. 서버가 사망 이벤트보다 먼저 인벤토리를 비울 수 있어 소지품은 마지막 생존 관측을 시각·출처와 함께 보존합니다. 이것은 실제 드롭 목록이나 소유권 확정이 아닙니다. 사망 원인은 자동 확정하지 않습니다. 리스폰 세대가 달라지면 이전 행동과 모델 응답을 무효화하고 새 위치/실제 인벤토리를 확인합니다. 기억과 이전 목표는 보존하되 장기 LLM이 현재 상태를 근거로 재검토합니다.

회수/준비/보류/포기는 근거가 있는 모델의 의도입니다. 사망 위치는 같은 차원의 기억한 목적지로 이동할 수 있지만 경로 발판은 현재 관측으로 확인합니다. 장비가 남아 있거나 위험이 사라졌다고 가정하지 않습니다. 줍기에는 실제로 보이는 아이템이 필요하고 회수 결과는 실제 인벤토리 변화로 확인합니다.

제한된 파일럿은 첫 사망에서 무조건 끝내지 않고 리스폰을 기다립니다. 세션 중3회 사망,30초 리스폰 대기 초과, 기존 저체력/반복 실패/시간/예산 보호 조건에서는 중단할 수 있습니다. 일반 CLI와 제한 파일럿의 운영 종료 정책은 구분됩니다.

## 회수 결과와 판단 갱신

사망 기억은 의도와 관측 결과를 따로 저장합니다. 최신 사망의 마지막 생존 소지품에서 리스폰 때 유지한 물자를 제외하고, 현재 인벤토리의 물품 종류·수량·인챈트를 비교합니다. 상태는 `unknown` → `unresolved`/`partial` → `supplies_restored`이며, 실제로 관측한 부족분이 채워졌을 때만 `resolved`로 정리합니다. 빈 손으로 죽었거나 유지한 물자만 있으면 회수를 성공했다고 만들지 않습니다.

- 보류/준비/포기 등 이전 판단과 부분 회수 결과는 시각·근거 ID와 함께 이력으로 보존합니다. 바뀐 결과는 기존 판단을 대체하고 장기 목표 재검토를 요청합니다(기존 최소30초 간격 유지).
- 장기 LLM은 새 관측 근거로 해당 회수 목표의 완료/수정 여부를 판단합니다. 더 넓은 생존 목표까지 자동 완료하지 않습니다. 중기/장기 호출 도중 회수 결과가 달라지면 오래된 응답은 적용하지 않습니다.
- 같은 물자를 여러 번 관측해도 누적 회수량으로 세지 않습니다. 드롭 실종·현장 방문만으로 완료하지 않습니다. 복구 뒤 물자를 사용해도 과거 완료 사실을 지우지 않습니다.
- `supplies_restored`는 물자 부족분의 해소이지 원래 드롭의 출처 증명이 아닙니다. 새로 만들거나 다른 곳에서 얻어도 부족분은 해소될 수 있고, 내구도·모든 NBT의 동일성까지 보장하지 않습니다. 일부 회수 후 사용한 물자는 별도 인벤토리 변화 기록으로 남고, 현재 부족분 판정에 중복 가산하지 않습니다.

이 후속 변경은 타입 검사·234개 테스트와 이전 서버 관측의 오프라인 재생으로 검증했습니다. 보류 이력 보존, 부분/완료, 재접속 복원, 인챈트 차이, 낡은 LLM 응답 차단, 회수 목표 완료 갱신을 모의검증했습니다. 실제 서버/API 재실행은 하지 않았고 비용은0입니다.


## 실행 지속성 후속 규약

JEV wait는 실행 중이면 유지, 실행이 없으면 대기다. 명시적 stop은 취소 요청이다. 비긴급 전환은 동일한 새 실행을3회 연속 고를 때 적용하고, 적 출현/피격/긴급 허기와 생명주기·사용자 목표 변경은 지연시키지 않는다. 신뢰도 임계치로 행동을 막지 않는다. 제작·설치·이동 후보는 계획에 근거하며 임의 레시피나 기억 속 블록을 별도 과제로 만들지 않는다.

봇별30초 무진전은 중기,90초는 장기 검토를 요청한다. 검토 요청 간격은 최소30초다. 기능검증 하네스는180초 무진전인 봇이 하나라도 있으면 종료한다. 이 수치는 실행 보호 규칙이며 학습된 게임 지식이 아니다. 관측 진전과 과제 성과는 별도로 평가한다.
