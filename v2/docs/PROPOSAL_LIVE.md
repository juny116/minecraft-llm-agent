# 제안 후 최종 판단: 실제 기능검증

2026-10-18 · MC-056. 선택형 `coordinated + proposal`의 짧은 서버 검증이다. 세부 목표를 주지 않고 같은 기준 월드와 새 봇 기억을 사용했다. 시작 인벤토리도 기준 복사본 그대로 유지했다. 본실험이 아니다.

## 중단 실행 L과 입력 한도 수정

L은 74.318초에 운영 중단했다. JEV context-limit HTTP400이 48회 발생했고, Alice 이동 실패1회·Bob 이동 성공5회/취소2회였다. 서버에서도 Bob 이동과 인벤토리·블록 변화 없음을 확인했다. 오류가 반복된 실행의 공백을 정상 성능 비교에 합치지 않는다. 비용은 $0.337216008이다.

원인은 관측 지도를 추가한 뒤 전체 목적지·누적 피드백이 함께 커져 공급자 입력 한도를 넘은 것이다. 관측을 삭제하거나 후보를 줄이는 대신 다음 전송 표현을 바꿨다.

- 정수 좌표 배열은 기준 좌표와 순서가 같은 차이값 배열로 표현한다. 소수 좌표는 반올림하지 않는다.
- 관측 지도에서 연속해서 같은 이름·관측 시각·가시성을 가진 행은 그 값을 한 번만 적고 좌표 순서를 보존한다.
- 질문 키, 선택지, 전체 관측값과 최종 철회 권한은 유지한다. 로컬 대체 행동은 없다.

실패 입력48개 모두 질문/상태/관측 지도의 완전 복원 일치를 확인했다. 직렬화 크기 평균66,515.75→58,710.23바이트, 최대66,912→59,101바이트였다. 바이트 감소를 토큰 감소율로 해석하지 않는다. 첫·중간·마지막 입력의 실제 API3회가 모두 정상 응답했고 비용은 $0.003318294였다. 이는 입력 수용성 검사이며 판단 품질 보장은 아니다. 타입 검사와387개 테스트가 통과했다.

`repack-context-check.ts --input=<events.jsonl>`은 저장 실패 입력을 무상으로 감사한다. `--with-api --authorized-total-usd=<budget>`을 추가하면 최대3개 실제 요청을 검사한다. 원본 로그와 운영 정보는 비공개로 보존한다.

## 정상 완료 M: 공백 개선 실패

M은120.009초 정상 종료했다. API851회(JEV782·LLM69), HTTP/입력 한도/decision 오류0이었다. 계획 오류2건(설명421자, 잘못된 장소 근거ID)은 검증에서 거절했고 다음 유효 계획은 각각13.022초·12.957초 뒤 나왔다. 정상 응답과 유효 계획을 구분한다.

| 지표 | 이전 K | 수정 후 M |
|---|---:|---:|
| 두 봇 평균 무실행 비율 |89.36%|97.39%|
| 이동 성공 |11|4|
| 실제 회전·보이는 블록 변화 없는 look |36/37|13/15|
| 블록 설치 성공 |5|0|

무실행은 실행 시작/종료 구간의 합집합을 전체 실행 시간에서 뺀 값이다. 명시적 idle 선택과 다르며, 실패·취소 행동도 실행 시간으로 센다. M의 Alice 무실행95.37%, Bob99.40%였다. Alice 이동4회, Bob 이동0회. 서버 독립 관찰도 Alice 약12블록 이동·순변위9.5블록, Bob 제자리, 설치·파괴·인벤토리 변화·전달0, 대화13건을 확인했다. 서로 다른 입력·질문 순서·표현 변화가 함께 있는 단일 실행이므로 K와의 차이를 한 변경의 인과 효과로 주장하지 않는다.

### 철회가 발생한 구체적인 지점

실행 루프에서 목적지 철회는152회였다. API 입력/출력을 요청ID로 대조하면 종료 직후 완료된 요청까지153회이며, **153회 모두 제안된 좌표가 해당 요청의 현재 위치에서 이미 도착 반경2 안이었다.** 같은 단계에서 반경 밖 좌표 bind8회, 반경 안 bind1회였다. bind는 실행 성공이 아니다. 실행 직전 최신 관측으로 이미 도착 판정된 결정4개는 별도로 버려졌고, 실제 이동은4회 성공했다.

따라서 이번 실패를 “유효한 먼 목적지를 골라도 최종 검토가 전부 거절한다”로 설명하면 틀린다. 좌표 제안 단계가 이동을 만들지 않는 가까운 좌표를 반복 고른 뒤 최종 검토에서 철회하는 패턴이다. 그룹/개별 질문에는 이미 도착 여부가 명시돼 있었다. 직렬화의 완전 복원이 모델의 해석 용이성을 보장하지는 않으므로, 압축 좌표 표현과 그룹 분할의 영향은 별도 비교가 필요하다. 선택 확률만으로 모델의 내부 이유를 단정하지 않는다.

JEV 단일 호출 중앙값266ms(p95 350ms), 전체 선택 절차 중앙값Alice1,228ms/Bob1,004ms였다. 무실행과 선택 요청 진행이 겹친 시간은Alice103.836초/Bob107.001초다. 이 중첩은 지연의 인과 기여량이 아니다. 빠른 개별 응답에도 다단계 제안→철회가 반복됐다. 호출 주기만 줄이면 해결된다고 볼 근거가 없다.

M비용$0.660234294, L+입력 수용성 검사+M 합계 **$1.000768596**. 이번 요청의 비용이며 이전 검증 비용과 구분한다. 반복 실험을 더 시작하지 않고 봇을 종료했다.
