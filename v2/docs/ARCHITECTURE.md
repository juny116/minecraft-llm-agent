# 구조와 동작 규약

## 판단과 실행

아래는 기본 `WORKFLOW_MODE=direct`의 계약입니다. 선택 기능을 보존한 v2.5 `procedural` 모드에서는 LLM이 범위를 제한한 수집·제작 절차를 만들고 로컬이 그 범위의 대상·재료 수량을 계산해 실행합니다. JEV는 절차의 시작·유지와 다른 행동으로의 전환을 판단합니다. [작업 절차의 위임 범위·기록](PROCEDURES.md)

| 층 | 구현 | 역할 |
|---|---|---|
| 목표층(장기) | LLM | 게임 설명·요청·관측을 바탕으로 활성 목표 1개와 근거·완료·중단 기록 관리 |
| 작업층(중기) | LLM | 현재 작업·조건부 후속 작업·완료 증거·재검토 조건 수립 |
| 행동층(실시간) | JEV | 행동 종류를 고른 뒤 관측된 도메인에서 대상·좌표·수량 선택 |
| 실행기 | 로컬 | Mineflayer와 경로 탐색으로 동작 수행, 물리 조건 검사·취소·결과 확인 |
| 대화·경험 | LLM | 목표층 결정에 따라 메시지에 응답하고 경험의 근거·반례로 지침 갱신 |

목표층은 항상 활성 목표 1개를 유지합니다. 완료 후에는 같은 검토에서 다음 목표를 고르고, 다른 목표를 활성화하면 이전 목표는 중단 기록으로 남습니다. 시작·사망·재접속·운영자 요청 변경 시에는 마지막 목표를 임시 목표로 표시하고 재검토 사유와 결정할 항목을 목표층·행동층에 전달합니다. 사망 시에는 경과 시간·아이템 소멸 시한(불확실)·사망 지점 거리·잃은 물건·당시 관측을 제공하며 진행 중인 작업은 무효화합니다. 게임 채팅의 요청은 제안이며, 자신에게 온 메시지가 오면 목표층이 즉시 수락·거절·보류·요청 아님을 결정하고 대화는 그 결정에 따라 답합니다(최대20초 대기). 경험 지침이 바뀌면 목표층을 재검토합니다. `/goal` 운영자 요청은 통제된 검증용이며 목표층이 충족 여부를 판정합니다.

JEV는 실행 중에도 유지·전환을 판단합니다. 요청 이후 실행 단계가 달라진 전환 응답은 적용하지 않고 최신 상태로 재판단합니다. 최신 판단의 중단 선택은 허용하며 채굴 유지를 강제하지 않습니다. 현재 작업·실행 시작 당시 계획·완료 기록을 구분하고, 기록·관찰과 실제 획득의 목적을 일치시키도록 모델에 안내합니다. 계획·대화 호출은 실행과 독립적으로 진행하며, 같은 역할의 중복 요청과 오래된 응답의 적용을 막습니다. 한 봇의 실제 액션은 한 실행기만 소유합니다. 낮은 신뢰도만으로 유효한 선택을 거부하지 않습니다. 명시적 사용자 목표가 있으면 초기 중기계획을 장기 검토와 병렬로 시작하며, 먼저 적용된 작업을 늦은 초기 장기 응답이 빈 계획으로 덮어쓰지 않습니다. 목표 변경·사망·재접속 뒤의 오래된 응답은 폐기합니다. 기본 `direct` 방식은 행동과 모든 인자를 선택하면 추가 모델 승인 없이 실행을 시도합니다. 인자 질문의 `revise`로 아직 실행하지 않은 제안을 철회할 수 있으며 별도 승인 호출은 없습니다. 기존 실행의 유지·중지는 행동 선택에서 결정합니다. 연속 판단 경로는 의도적인 `wait`/`idle`과 대기 시간 선택을 제공하지 않습니다. `continue`는 실행 중 작업을 유지하고 `stop`은 취소 후 재판단하며, 다른 행동을 자동 선택하지 않습니다. 이전 기록·비연속 도구 호환용 `idle` 자료형은 남아 있습니다. `place_table`도 과거 도구 호환용이며 현재 사방 관측 선택지는 `place_block(item=crafting_table)`로 통합합니다. 빈 선택 범위·잘못된 응답·실행 직전 조건 변화는 실행하지 않고 기록합니다. 기존 승인 방식은 비교용 설정으로 남아 있습니다.

기본 `TARGET_POLICY=observed`에서는 LLM이 구체적인 대상 목록 대신 작업 의도를 제공합니다. JEV의 선택 범위는 사전 구현된 액션과 관측에 근거한 유한한 인자 도메인입니다. 로컬 코드는 경로 탐색·물리 검증을 수행하지만 임의의 대체 행동을 선택하지 않습니다.

계획의 요청·적용 시각과 요청 당시 실행/재료 상태를 기록합니다. `planFreshness`는 이후 완료 기록·재료 변화·현재 실행을 함께 전달하며, 오래된 계획 문장을 현재 사실로 승격하지 않습니다. 생성 중 재료나 절차 상태가 바뀌면 중기 검토를 다시 요청하되 현재 행동과 목표를 자동 교체하지 않습니다. 완료된 절차는 `lastProcedure` 이력으로 전달하고 진행·재개할 작업과 구분합니다.

중기 LLM은 이전 작업의 `taskReview`(계속·완료·보류·교체, 근거 참조, 남은 조건)와 새 작업을 함께 반환합니다. 적용된 최근8건을 다음 계획에 전달하며, 장기 목표를 자동 완료하거나 액션을 제한하지 않습니다. 참조 유효성 검사는 의미상 완료의 증명이 아닙니다. 이 검토 이력은 현재 세션 범위이며 재시작 복원은 후속 과제입니다. 상자 내용은 마지막 상호작용 시각·경과 시간과 함께 표시하고 진행 중인 검사를 완료 결과와 구분합니다.

`stop`은 대체 행동 없이 즉시 중단할 때 사용합니다. 다른 행동을 직접 선택하면 기존 실행 중에 인자를 준비하고 검증 후 전환합니다. 사방 관측 경로는 행동별 최대254개 인자를 직접 선택하며 구역·그룹 선택을 추가하지 않습니다. 현재 반경 밖의 작업은 먼저 이동하고 다시 관측해야 합니다. `actionAvailability`는 행동별 현재 인자 목록·재질별 개수와 범위 밖의 관측 자원을 구분합니다. 경로 성공이나 목표 적합성을 보장하지 않습니다. 철회 기록에는 당시 후보와 이미 정한 인자가 남고, 다음 판단에는 요약과 후보 변화 여부가 전달됩니다. 실행 중 공격 대상은 관측된 동물·적 ID와 연결하며 숨은 체력은 제공하지 않습니다. 긴급 중단은 유지합니다.

제작 관측에는 서버에서 해금한 지원 제작법의 재료별 보유량·1회 부족분·산출 수량·실행 가능 횟수(최대16회)가 포함됩니다. 실제 서버 제작법 ID로 변형을 구분해 미해금 방법은 제외하고, 재료 소비·획득 후 다시 계산합니다. 제작 가능성은 목표에 유용하다는 뜻이 아니며, 부족한 재료의 확보 순서는 모델이 정합니다.

## 관측과 기억

주변은 시선과 무관하게 자동 관측합니다. 눈 위치 기준12블록 이내는 블록별 노출 면에 대한 가림 검사를 추가하고,48블록까지는 광선의 첫 충돌 표면을 표본 관측합니다. 벽 뒤·미관측 공간을 채우지 않으며 실제 서버에서 `look`은 선택지에 없습니다. 여섯 축의 가림 정보는 해당 광선에만 적용합니다. 이는 사람 화면의 재현이 아닌 기하학적 감지이며 투명·부분 블록과 원거리의 세밀한 가시성은 한계가 있습니다.

가까운 지도는 재질·높이·관측 시각이 같은 정확한 직사각형 영역으로 압축합니다. 구멍·다른 블록·과거 관측을 합쳐 채우지 않고 셀 수에 따른 잘라내기도 하지 않습니다. 현재 관측과 과거 지형을 분리하며, 미기재 공간은 공기나 안전한 통로를 의미하지 않습니다. 원거리는 방향·거리대별 요약을 제공합니다. 설치 가능한 빈칸과 지지 블록은 지도에서 영역으로 압축하되, 선택 시에는 정확한 위치를 제공합니다. 사방 관측 모드에서는 재료와 위치를 같은 요청에 묻습니다. 같은 설치 칸의 여러 지지 면은 하나로 연결하며, 어떤 칸에 설치할지는 모델이 선택합니다. 후보는 접근·설치 성공을 보장하지 않으며 작업 실행 시 다시 검사합니다. 로컬 코드는 목표에 맞는 위치를 대신 고르지 않습니다.

일반 지형은 봇별 청크 파일에 관측 시각과 함께 저장합니다. 입력에는 현재48블록 이내 정보만 조회하고 원거리 기록은 디스크에 남겨, 탐험 이력 전체가 매번 누적되지 않게 합니다. 중요 장소는 LLM이 지정한 전체 목록을 별도로 제공합니다. 대화에서 들은 장소는 발화자와 함께 전달하며 직접 관측으로 승격하지 않습니다. 따라서 중요 장소·경험 지침의 증가와 복잡한 근거리 지형의 입력 크기는 후속 검증 대상입니다. 원거리 지형을 모델이 능동 검색하는 인터페이스도 아직 없습니다.
중요 장소에는 좌표·관측 시각·변경 상태가 남습니다. 장소 기록은 LLM의 `placeUpdates`로 처리하며 게임 액션이 아닙니다. 최근8건의 적용·변경 없음·거절 결과를 장소 참조와 함께 중기·장기 LLM 및 JEV에 전달하고 재접속 후에도 복원합니다. 기억 갱신만으로 목표를 자동 완료하지 않습니다. 서버가 제공하는 전체 지도나 상대 인벤토리·숨은 체력을 모델에게 제공하지 않습니다. 제작법 입력은 해당 봇의 서버 해금 기록을 사용하며 LLM의 사전 지식은 제한하지 않습니다.

경험·지침, 사회적 기억, 장소·보관함, 자율 목표는 봇별로 저장합니다. JEV에는 활성 경험 지침 전체를 조건·불확실성과 함께 전달합니다. LLM은 새 경험 검토와 주기적 전체 정리에서 중복을 병합하고 반례에 따라 수정·보류합니다. 새 경험이 없어도 5분마다 정리하며, 지침집이 약 6,000자를 넘으면 1분 간격으로 검토합니다. 원본 경험·근거·이전 버전은 보존하고 검증된 변경만 한 번에 적용합니다. 채팅과 오래된 관측은 확인된 현재 사실로 취급하지 않습니다. 재접속 시 목표를 현재 관측으로 재검토하며 사용자 요청·이전 작업을 그대로 재실행하지 않습니다.

현재 관측·실행 기록·선택지의 중복 객체와 문장은 ID로 공유하고 좌표·시각은 기준값과 차이값으로 무손실 압축합니다. 직전 결과는 상태 변화 중심으로, 선택 피드백은 짧은 사실 문장·대상·상태·횟수로 전달합니다. 피드백은 로컬 행동 규칙이 아닙니다. JEV와 중기 LLM에는 연속된 같은 시선의 완료·관측 변화 없음, 목적지별 실패 횟수와 마지막 진단을 함께 전달합니다. 경로를 찾지 못한 경우 탐색 상태·시간 한도·끝점·높이 차·탐색 중 직접 관측한 주변 블록을 기록하며, 높이 차만으로 불가능 원인을 단정하지 않습니다. 완료된 이동도 실제 출발·도착 위치와 완료 반경으로 요약하며, 경로 전체의 안전이나 채굴 가능성을 보장하지 않습니다. 중기 LLM은 이동·채굴 실행 규약을 함께 받고, 접근 조사에는 판단을 바꿀 증거와 종료·보류 조건을 명시하도록 안내합니다. 중기 계획은 `next/then/done/blocked` 작업 지침을 기존 의도 필드에 최대6항목·항목당500자로 작성하도록 요청합니다. 이는 실행 큐나 액션 제한이 아니며, 단계의 의미·완료 여부는 모델이 판단합니다. 현재·과거 계획과 진행 중·완료된 결과를 구분하도록 지시하며 기존 원본 근거는 유지합니다. 반복은 행동 금지 조건이 아닙니다.

## 결과를 기록하는 기준

모든 실행은 작업 대상·마지막 확인 단계·경과 시간·시작/종료 위치·인벤토리 변화·오류 원인을 `actionEvidence`로 남깁니다. 제어의 성공/실패/취소와 실제 반영된 변화는 별개이며, 채굴·전투 등의 기존 구조화 결과도 보존합니다. 상자는 요청 수량과 인벤토리/보관함 양쪽 변화가 일치하는 수량·잔량을 구분합니다. 화로 처리나 확인되지 않은 변화는 미확정으로 남깁니다.

- `craft`: 작업대가 필요한 경우 JEV가 관측·근거리 기억의 작업대를 선택합니다. 실행기는 접근·현장 재확인·제작을 수행하며 재료 수집이나 작업대 설치를 자동으로 하지 않습니다. 여러 번 제작하다 취소돼도 실제 인벤토리 변화는 남습니다.
- `follow`·`give`: 보이는 동일 대상을 접근 중 재확인합니다. 대상 유실은 중단·실패로 보고하며 숨은 실시간 좌표를 따라가지 않습니다. 접근 실패에 다른 플레이어를 대신 선택하지 않습니다.
- `pickup`: 대상 유실 시 추적을 중단하고 실제 인벤토리 획득을 따로 확인합니다. 채굴 뒤에는 제한된 줍기 시간 안에서 늦게 나타난 드롭도 재확인합니다.

- `mine`: 관측하거나 근거리 기억에 있는 블록 하나에 접근·재관측·채굴·짧은 줍기를 수행합니다. JEV는 블록과 도구를 선택하고 시간은 선택하지 않습니다. 실행기는 장착 후 블록·도구·효과·물속/공중 상태로 시간을 추정해 여유를 더합니다(최대10분, 추정 불가 시30초). 진행 입력은 단계·경과·예상 남은 시간·실행 제한이며 실제 파괴 진행률은 아닙니다. 중단은 계속 가능하며, 블록 파괴, 드롭 관측, 실제 인벤토리 획득을 구분합니다. 시간 초과는 채굴 불가능의 증거가 아닙니다.
- 작업 대상과 접근: 설치 후보는 눈 위치 기준 최대 반경12블록 안에서 현재 관측한 면과 빈칸을 사용합니다. 이동·채굴·설치·줍기·작업대·보관함별 후보가254개를 넘으면 반경 전체를1블록씩 줄입니다. 실제 반경·후보 수·범위 밖 수를 `actionScopes`로 LLM과 JEV에 함께 제공합니다. 재질·방향·목표에 따른 후보 순위는 없습니다. 짧은 접근은 포함하지만 더 먼 설치는 먼저 이동하고 다시 관측해야 합니다. 채굴·상자 대상도 현재 선택 반경 안의 관측·기억을 사용하며 현재 관측이 우선합니다. 더 먼 지형과 중요 장소는 지도·기억에 남습니다. 실행기는 접근 후 거리·가림·대상 상태를 재확인합니다. 후보는 경로·성공 보장이 아니며 실패 시 다른 대상이나 지형 변경을 자동 선택하지 않습니다. 설치는 현재 `air` 칸만 지원합니다.
- `place_block` (제작대 포함): 접근·준비·장착·조준·요청·확인 단계를 판단 입력에 제공합니다. 취소는 이미 서버에 반영된 설치를 되돌리지 않습니다. 실행 결과와 별도로 요청 여부·블록 일치·아이템 변화·확인 여부를 기록하며, 취소 뒤에도 확인된 효과를 다음 판단과 계획에 전달합니다. 확인되지 않은 경우 뒤늦은 반영 가능성을 배제하지 않습니다.
- 관측은 시선과 무관하게 자동 갱신합니다. 이전 기록·비교 도구 호환용 `look` 자료형과 실행 코드는 남아 있지만 실제 사방 관측 모드에서는 선택할 수 없습니다.
- `move`: 목적지 블록 셀의 반경2 안까지 접근합니다. 정확한 좌표에 서는 기능은 아닙니다. 이미 도착한 좌표는 관측·기억에 유지하되 새 이동 인자에서 제외합니다. 설명·선택·실행은 같은 완료 기준을 공유합니다. 목적지 기억은 경로 성공을 보장하지 않습니다.
- `equip`: 행동 선택 후 아이템의 기본 착용·보조 손 들기·부위 해제 중 하나를 선택합니다. 방어구는 부위를 자동 연결하고 일반 아이템의 기본은 주 손입니다. 보조 손 선택은 일반 아이템에만 제공합니다. 전체 인벤토리에서도 최대88개 변경으로, 장비 선택은2회 호출이며 별도 부위 선택이나 그룹 분할이 없습니다. 같은 이름의 장비도 출발 슬롯으로 구분하며 로컬 코드가 장비를 추천하지 않습니다.
- `give`: 아이템을 떨어뜨린 결과를 기록하며 상대 수령은 자동 확정하지 않습니다.
- 전투: 관측한 적·동물의 공격과 도주는 모델이 선택합니다. 로컬 스킬은 접근·공격 대기·반복 타격·재관측의 진행상태, 자체 시간 상한과 보낸 공격 횟수를 전달합니다. 이는 상대 체력 정보가 아닙니다. JEV 중단·전환은 `interruption` 출처와 당시 진행상태로 남겨 물리 실패와 구분하며, 취소 권한은 유지합니다.
- 사망: 자동 리스폰 후 마지막 생존 관측과 현재 장비·위험을 바탕으로 회수 여부를 검토합니다. 사망 기록만으로 드롭이 남아 있다고 가정하지 않습니다.

## 코드 위치

`providers`·`parameter-supervisor`: 모델 호출과 선택 / `runtime`·`planning`·`goals`: 제어와 계획 / `vision`·`spatial-memory`·`experience-memory`: 관측과 기억 / `mining`·`building`·`combat` 등: 로컬 액션.


Task identity: each accepted medium task has a taskId and completion-criterion IDs. Continue preserves both; new work gets a new ID. Reviews bind each condition to supplied evidence and an explanation. Wrong task/criterion IDs and unresolved conditions cannot mark a task complete. Execution records retain their starting task ID. Semantic relevance remains a model judgment.

Medium/long plans, experience reflection and medium-plan place annotations permit one bounded model repair using the same evidence and exact error. Request-local short evidence references are restored to canonical IDs before validation and storage; unknown references remain invalid. Length errors identify each offending field. Runtime atomicity and stale checks remain authoritative. Conflicting constraints fields are rejected; an unambiguous misplaced field is moved without data loss. Neither prose nor evidence lists are truncated to pass validation. Budget and stale-response checks remain in force.


The ordinary map overview is bounded to 16,000 UTF-8 bytes (a conservative token bound), excluding separately supplied important places and other context. Compact terrain retains exact regions; irregular terrain uses a smaller exact neighborhood plus directional summaries. Placement geometry is expanded only during argument selection when the overview cannot fit. Full observed domains remain local and selectable; summaries never imply filled or traversable space. Live panorama selection uses explicit local action scopes rather than hierarchical argument calls. All targets inside each reported scope remain selectable; outside targets remain in observation/memory. Legacy replay paths retain hierarchy. Nonspatial domains over254 fail explicitly rather than truncate or silently add rounds.

사방 관측의 호출 단계: 이동·설치·줍기·장비·먹기·추적·전투·상자 확인은2회, 채굴·작업대 제작·전달·보관·인출은최대3회입니다. 제작 수량과 작업대는 묶고, 보관·인출은 선택한 보관함의 아이템·슬롯과 항목별 조건부 수량을 한 요청에서 결정합니다. 선택되지 않은 항목의 수량은 적용하지 않습니다. API 재시도는 논리적 선택 단계 수와 별개입니다.

침대는 `place_block`에서 발 위치와 동서남북 방향을 선택합니다. 두 칸의 빈 공간·관측한 바닥을 재검사하고 머리/발·방향·아이템 감소를 확인합니다. `sleep`은 관측한 근거리 침대를 선택해 접근하고 서버의 수면·기상을 기다리며, 중단하면 깨어납니다. 오버월드에서만 지원하고 낮·점유 등 서버 거절은 실패로 기록합니다. `attack`은 관측한 양·소·돼지·닭·토끼·무시룸도 대상으로 선택할 수 있습니다. 동물은 적대 목록과 별도로 전달하며 사냥·장비 선택·드롭 줍기는 모델이 결정합니다. 가위질과 문 설치는 아직 미지원입니다.

전투 실행은 로컬 동작입니다. `attack`은 대상이 죽을 때까지 최대 8초 동안 추적·공격하고, 쿨다운 동안 가까운 대상에게서 한 칸 물러납니다(뒤쪽 바닥이 없거나 액체·다른 적이 있으면 제자리). `flee`는 보이는 모든 적에게서 가장 먼 기억된 바닥으로 달리고, 24블록 안에 적이 없을 때까지(최대 18초) 경로를 다시 정합니다. 로컬 서버 확인 기준으로 돌검은 좀비 1~2마리를 잡지만 3마리 이상이나 맨손 전투는 이기지 못합니다.
