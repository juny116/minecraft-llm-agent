# 같은 방향 look: 입력 감사와 결과 의미 보강

2026-10-18 · MC-056.

**후속 정정:** 이 재생 도구는 모델 observation에서 과거 `places`를 복원하지 못해 다른 행동으로 전환할 때 이동 도메인이 축소됐다. 따라서 아래 이동 완료/철회 수치는 제한 도메인 진단이며 실제 서버의 전체 목록 결과가 아니다. 원본349입력 감사와 look 의미/반복 이력 전달 검증은 유효하다. 도구에 부분 도메인 명시 승인 플래그를 추가했고 이후 이동 진단은 실제 목적지 질문의 전체 값을 직접 재사용한다. [이동 진단과 정정](MOVE_CONTEXT.md).

 **직전 무변화 결과와 현재 시야가 실제 입력에 있었다.** 누락/타이밍만으로 반복을 설명할 수 없다. 수정 후 같은 방향 선택은 줄었지만 목적지 철회로 옮겨가 실행 공백 해결은 입증하지 못했다. 서버 재접속이나 본실험 없이 저장 입력만 진단했다.

## 확인한 사실

직전120초 회차의 입력과 같은 봇의 완료 기록을 시간순으로 대조했다. 직전 look의 실제 회전·가시 블록 변화가 모두0인 뒤의 JEV 입력349건(행동115, yaw164, pitch70) 전부에 다음이 포함됐다.

- 가장 최근 완료 기록과 동일한 `recentOutcome.id`
- 같은 `recentOutcome.changes.view`: 회전량0, 들어온/나간 블록0
- 현재 `observation.vision`의 yaw/pitch/전체 가시 블록

마지막 반복 사례의 상위 계획도 이미 반복 관찰을 피하고 의도를 재검토하라고 명시했다. 이를 새 정보 부족이나 무조건적인 계획 미갱신으로 해석하면 안 된다. 반면 `recentResults`는 look/idle을 제외해 반복 look의 연속 기록을 보여주지 않았다. 원본 직전 기록은 상세 구조 안에 있었고 motor 결과는 `succeeded / Completed look`였다. 이는 관측 진전과 다른 사실이다. 모델이 실제로 어떤 필드를 이해했는지나 내부 원인은 확인할 수 없다.

## 수정

- 최근12행동의 retained journal에서 최근look 최대6건을 별도 전달한다. ID·종료시각·요청 각도·완료 상태·실제 시야 변화만 연결한다. 기록이 없으면 무변화라고 추정하지 않는다. 원본 recentOutcome/recentResults/전체 시야/중요 지도는 유지한다.
- 현재 카메라와 반복 관측을 `lookFeedback`에서 명시적으로 연결한다.
- 동작 의미: look는 몸을 이동하지 않고 절대 시선 각도를 설정한 뒤 관측한다. 일반 snapshot도 별도로 관측하므로 look가 현재 정보를 받기 위한 필수 동작은 아니다. motor 완료는 새 정보 획득을 뜻하지 않는다. 같은 방향 유지로 변화하는 장면을 감시할 수도 있으며 이를 금지하지 않는다.
- 모든 행동/각도/철회/대기를 유지한다. 강제 회전·임의 이동·선호 좌표·실패 시 대체 행동은 추가하지 않았다. 요청/응답 계약과 로컬 실행기는 유지했다.

타입 검사·380테스트 통과. 원본 보존, 무손실 전송, view 미관측 처리, 실제 provider를 통한 반복 이력 전달과 bind/withdraw를 검증했다. 초기 테스트의 undefined 필드와 JSON 직렬화 비교는 JSON 표현 기준으로 수정했다.

## 같은 입력 API 검증

두 봇 각각 반복 구간의 중간/마지막 행동 입력을 뽑아4관측×2반복×2조건,16개의 전체 행동→인자 판단을 수행했다. 조건 순서를 번갈아 실행했고 별도 철회 gate는 양쪽에서 동일했다. 실제 게임 실행은 없었다. 실패 구간에 편향된 작은 표본이며 일반 플레이 분포를 대표하지 않는다.

| 최종 비교 | 기존 입력 | 수정 입력 |
|---|---:|---:|
| 판단 |8|8|
| 거의 같은 방향 look 선택(요청 변화<1도) |4|0|
| 다른 방향 look 선택(≥1도) |0|0|
| 이동 인자 선택 완료 |2|2|
| 인자 미해결/철회 |2|6|
| API 호출 |42|24|
| 전체 판단 평균 지연 |1,534ms|729ms|

**반복 look가 실행 가능한 대안으로 바뀐 것은 아니다.** 수정 조건에서는 이동 행동을 고르지만6건이 목적지 단계에서 철회했다. 이동 선택2건도 서버 경로 성공이나 작업 진전으로 세지 않는다. 공백이 줄었다는 주장은 하지 않는다.

탐색적 분리 비교에서는 행동 의미 설명만 추가하거나, 의미 문구 없이 반복 이력/현재 카메라를 드러내는 경우 각각8판단 중 이동 선택2·철회6·look0이었다. 원본에 없던 전략을 강제해야만 바뀌는 것은 아니라는 증거지만 효과 크기나 일반화는 확정하지 않는다.

초기 문구의 “관측 버퍼를 갱신하지 않는다”는 표현이 오해를 줄 수 있어 실제 look 후 observe와 일반 snapshot 관측을 구분하는 문구로 정정하고 위 최종16판단을 다시 실행했다. 초기 비교/분리 비교 원본과 비용은 보존했고 최종 결과에 합치지 않았다.

총182 API 호출, 비용 **$0.093584022**(초기$0.035168658 + 분리$0.024419976 + 최종$0.033995388), 모두 JEV. HTTP 오류 없이 완료했다. raw 요청·응답·원장·349건 감사 매핑은 비공개 보관한다.

## 다음 판단

문제는 “아무 정보도 못 받음”보다 입력 표현에 민감한 모델 선택과 행동/인자의 불일치에 가깝다. 이 수정은 반복 관찰을 드러내는 입력 보강이며 공백 해결책으로 검증된 것이 아니다. 현재 서버 재실행보다, 동일한 move 의도를 고른 직후 왜 전체 목적지에서 withdraw하는지를 관측·도메인·목표 연결 기준으로 좁혀 진단하는 것이 우선이다. 인간 동반 자율 플레이 준비 완료는 아직 아니다.

재현: `scripts/look-feedback-replay.ts --with-api --input=<private-events.jsonl> --authorized-total-usd=<approved-total>`; `--ablation`은 분리 진단. 과거 로그에는 `--partial-domains-diagnostic`을 명시해야 실행되며 전체 행동 비교로 해석하면 안 된다. 도구 자체는 Minecraft에 접속하지 않고 비용/호출 상한을 공유 원장에 기록한다. [앞선 서버 결과](JEV_WITHDRAWAL_LIVE.md).
