# 게임 설명·목표·기억

## 입력 계약
| 입력 | 역할 | 갱신 주체 |
|---|---|---|
| gameContext | 생존·생활 개선·탐색·협력의 공통 배경; 집·직업·수집 순서 강제 없음 | 개발자/사용자 |
| userRequest | 실행 중 사용자 요청/제약, 봇의 목표와 별개 | 사용자 |
| state | 현재 직접 관측 | 게임 |
| memory | 경험 지침, 사회적 기억, 관측한 장소·컨테이너 | 저장/검색 계층 |
| planning.goalReview | 기존 목표·근거·현재 관측 ID | 런타임 |

`src/goals.ts`의 GAME_CONTEXT가 고정 설명입니다. 모델은 이를 갱신하지 않습니다. LLM이 goalUpdates와 activeGoalId를 반환하고, 코드가 적용합니다. gameContext는 플레이어 채팅으로 덮어쓰지 않습니다.

## 목표 객체
id, description, reason, evidenceIds, successCriteria, status, pauseReason(보류 시 필수), version, createdAt, updatedAt.

상태는 active / paused / completed / abandoned. 진행 목표 최대1개, 진행+보류 최대8개, 전체32개입니다. 같은 목표는 ID를 유지하고 교체 시 이전 목표를 명시적으로 보류/종료해야 합니다. 보류 목표를 덮어쓰지 않습니다. 종료 목표는 다시 열지 않고 필요하면 새 목표를 만듭니다. 용량 초과는 명시적으로 거절하며 장기 캠페인용 무제한 관리가 아닙니다.

이유와 완료 기준은 LLM 작성입니다. 근거는 런타임이 제공한 관측·행동·사용자 요청 ID만 인용할 수 있습니다. 활성화/완료에는 이번 관측 ID가 필수입니다. **인용의 존재는 코드로 확인하지만, 자연어 완료 기준의 의미적 충족은 모델 판단**입니다. 목표 완료 선언을 실제 아이템 획득/처치 증거로 사용하지 않습니다. 단계 완료는 기존 관측 조건으로 별도 검증합니다.

## 저장·재접속
표준 CLI는 봇별 프로필 아래 goals.json을 저장합니다. 목표, 근거, 최대128개 수정 이력을 유지합니다. 잠금·버전 검사·원자적 교체를 사용하고 손상/프로필 불일치를 보존한 채 거절합니다. 목표가 인용한 근거는 보존하며 최근 미인용 근거는 제한합니다.

재시작/연결 변경 시 일반 작업을 막고 목표를 재검토합니다. 현재 관측을 인용한 재활성화가 성공해야 새 계획을 실행합니다. 이전 단계/좌표를 자동 재생하지 않습니다. 사용자 요청 변경도 활성 목표를 보류하고 재검토합니다. 새 사용자 요청은 세션 입력이므로 재접속 시 필요하면 다시 지정해야 합니다.

검토 실패 중에도 긴급 먹기와 보이는 위협 대응은 가능합니다. 새 요청 이후 도착한 오래된 검토 응답은 저장/실행하지 않습니다. 이는 자동 네트워크 재접속 기능을 추가한 것은 아닙니다.

## 역할별 정보량
LLM: 게임 설명·사용자 요청·관측·관련 기억·목표 목록·최근 실행 증거.
JEV: 사용자 요청·활성 목표/단계·실행 파라미터·최근 결과·현재 관측·관련 지침. 전체 목표 수정 이력, 전체 제작법 목록, 장기 장소 목록은 보내지 않습니다. 현재 craftable과 시야는 유지합니다.

표준 CLI의 mock/live에 연결했습니다. GoalBook 옵션을 주지 않는 기존 단위 fixture/진단 하네스는 이전 계획 계약을 지원합니다. 파일럿은 반드시 새 목표 관리가 연결된 표준 경로를 사용해야 합니다.

검토 오류는 plannerFeedback으로 다음 요청에 전달하고 새 관측 ID를 강조합니다. 잘못된 근거를 자동 치환하지 않습니다. 형식·근거 오류는 1초 이후 새 관측으로 재시도하며, 두 번 실패한 행동은 재계획이 성공하기 전 반복하지 않습니다. 위협 대응·긴급 먹기는 유지합니다. 접속 종료로 인벤토리 관측이 사라진 경우 아이템 손실로 계산하지 않습니다.

## 종료 목표 재확인과 장기 오류 피드백
종료 목표의 ID·상태·설명·완료 기준이 정확히 같으면 재제출을 무변경으로 허용합니다. 기존 이유·근거·버전·시각은 덮어쓰지 않습니다. 다른 종료 상태로 변경하거나 재활성화/기준 변경은 거절합니다. 근거 ID는 무변경 항목도 검사하며, 새 목표를 포함한 전체 응답의 활성 목표·용량·현재 관측 검증은 유지합니다. 잘못된 응답은 부분 저장하지 않습니다.

독립 장기 호출은 longPlannerFeedback으로 직전 검증 실패 이유를 받습니다. 중기 계획 성공이 이 피드백을 지우지 않으며, 장기 검토 성공 또는 요청/생명 세대 변경 때 초기화합니다. 기존 재시도 간격은 유지합니다.241개 모의검증 통과, 이 변경의 실제 모델/서버 검증은 아직 하지 않았습니다.
