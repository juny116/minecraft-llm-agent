# 구현 명세
LLM은 장기 목표·중기 단계를 갱신하고, JEV는 즉시 실행할 스킬을 선택합니다. 로컬 실행기가 동작을 완료·취소하며 실제 결과를 확인합니다. 대화와 경험 검토도 동일 API 예산을 공유합니다.

| 모듈 | 역할 |
|---|---|
| cli/config/control | 설정, 시간·비용 제한, 실행 중 목표 변경 |
| providers/runtime/planning/goals | 모델 통신, 행동 소유권, 재계획, 증거 연결 |
| mineflayer/vision/protocol/recipe-book | 연결, 시야, 버전별 패킷, 제작법 해금 |
| combat/building/mining/pickup/equipment | 로컬 스킬과 결과 확인 |
| experience-memory/social/spatial-memory | 경험·대화·장소 저장 |

한 봇의 동작은 한 실행기만 소유합니다. 새 목표·대화·위협·계획 변경에 오래된 응답을 폐기합니다. 낮은 JEV 신뢰도만으로 유효 행동을 거절하지 않습니다.

채굴 성공과 획득, 전달과 수령, 적 실종과 처치를 구분합니다. 관측·실행 제약은 가이드라인보다 우선합니다. VISION_AND_ACTIONS.md와 PLANNING.md 참고.

게임 설명·사용자 요청·자율 목표·기억 입력을 분리합니다. 목표의 저장·근거·보류·재접속 게이트는 GOALS.md가 기준입니다.

## 계획 입력과 실행 일치
- 현재 시야와 오래된 장소 기억을 구분합니다. 첫 단계가 현재 불가능하면 목표 검토는 유지하고 불가능한 후보만 제외해 다른 합법 행동 선택과 재계획을 허용하며, 기억 속 장소는 이동·재관찰에 사용할 수 있습니다.
- 도착 기준은 pathfinder와 같은 블록 셀 거리입니다. 이미 도착한 이동은 반복 후보에서 제외하고, 무동작 이동은 파일럿 진전으로 세지 않습니다.
- 같은 대상·같은 조건의 두 번 실패는 계획 ID를 바꿔도 재시도하지 않습니다. 위치·인벤토리·관련 제작 가능성 변화나 더 적은 제작 수량은 재검토할 수 있습니다. 불가능하다는 학습 결론이 아닙니다.
- 목표 근거의 과거 시야는 모델 입력에서 블록 종류별 개수로 요약하고, 현재 관측은 별도 state를 참조합니다. 근거 ID·원본 기록·최근 JEV 선택/결과/상태 변화는 보존합니다. 디스크 기억을 지우거나 요약으로 덮어쓰지 않습니다.
- 제작 실패는 작업대 미관측과 부족 재료를 구분합니다. 구체적 레시피 정보는 서버가 해금한 vanilla 출력 ID에 한해 제공합니다. 해금되지 않은 레시피의 LLM 사전 지식에 의한 시도는 가능하지만, 실패 시 비공개 레시피 내용을 노출하지 않습니다.

가이드라인 검토는 새 경험과 기존 근거 외에도 같은 행동의 과거 성공/실패를 소수 함께 조회합니다. 새 경험의 검토 순서를 건너뛰지 않으며, 근거가 부족하면 갱신하지 않은 이유를 요청합니다.

## 독립 제어 루프
현재 실행 계약은 [CONTROL_LOOP.md](CONTROL_LOOP.md)를 따릅니다. JEV는 실행 중에도 선택하며 LLM 계획은 직접 액션을 시작하지 않습니다. 목표와 중기 계획은 별도 모델 호출이고, 대화의 수신자/별명은 의미 기반 분류와 근거 있는 기억으로 처리합니다. 사망 기록은 현재 위험/드롭 존재를 보장하지 않습니다.
