# 중요 장소 지도

중요도는 중기 LLM이 판단한다. 로컬 코드는 좌표와 근거를 검증하며 작업대 같은 블록 종류를 자동으로 중요 장소로 지정하지 않는다.

- `placeEvidence`: 직접 관측한 블록의 근거 ID, 차원, 좌표, 종류, 관측 시각. 기존 중요 장소도 재검토할 수 있다.
- `placeUpdates`: LLM이 근거 ID, 짧은 이름, 중요한 이유, active/archived를 반환한다. 한 응답의 변경은 최대12개, 저장된 지도 개수에는 상한을 두지 않는다.
- `important-places.json`: 봇/프로필별 영속 지도와 변경 이력. 동일 차원/좌표는 안정적인 ID로 갱신한다. 원본 장소/행동 기록은 별도로 보존한다.
- 지도 전체를 JEV·중기·장기·대화 입력에 전달한다. 거리나 최근 관측 순위로 등록된 장소를 누락하지 않는다. 변경 이력 원문은 매번 전달하지 않는다.
- 중요 지도는 현재 시야가 아니다. 과거 관측 시각·마지막 블록·changed 상태를 전달한다. 새 직접 관측은 상태를 갱신하지만 중요도는 바꾸지 않는다. 늦은 계획 응답은 더 최신 관측을 덮어쓰지 못한다.
- 알려진 장소를 archived로 표시해도 지도와 이력에서 삭제하지 않는다. 재접속해도 유지한다. 차원 간 좌표를 혼동하지 않는다.

현재 구현은 기본 observed 중기 계획 응답에서 중요도를 갱신한다. JEV와 다른 LLM 역할은 지도 전체를 읽는다. 직접 관측 기반 점 좌표만 등록하며, 임의 영역·상대방에게 들은 미확인 좌표·독립 사건 기억의 LLM 큐레이션은 아직 구현하지 않았다. 사건은 기존 행동 기록/경험 기억이 담당한다.

새 장소 후보는 기존 관측/공간 기억 경로를 사용하므로 아직 중요하다고 등록하지 않은 장소가 요약 이전에 빠질 가능성은 남는다. 기존 지도/원본 기록을 자동 변환해 중요 장소라고 선언하지 않는다. 다음 실제 검증에서 중요도 선택 자체와 후보 전달 누락을 구분해 측정한다. 중요한 지도가 커지면 입력 크기를 계측하고 정책을 재논의한다. 자동 top-k 생략이나 벡터 검색은 넣지 않았다.

타입 검사 및315개 모의검증 통과. 20개 등록 장소 전체 전달, 재접속, 좌표 근거 검증, 일괄 검증 원자성, 차원 분리, 상태 변화/늦은 응답, 중기 응답→런타임 저장→JEV 입력 연결을 검사했다. 실제 LLM이 유용한 중요 장소를 선택하는지는 아직 검증하지 않았다. 유료/서버 실행 없음.
