# 개발 시행착오 기록

프로젝트 시작부터 현재까지 확인 가능한 사용자 논의·커밋·기능 문서·실행 기록을 역으로 대조해 정리했습니다. 기록 범위는2026-10-15~17입니다. 과거에 기록하지 않은 실패를 새로 만들어 넣거나 원인 추정을 확정 사실로 바꾸지 않습니다. 기능의 첫 추가를 전부 버그 해결로 포장하지 않고 설계 결정도 함께 남깁니다.

빠른 소개는 [프로젝트 사례](PORTFOLIO.md), 현재 수치는 [통합 파일럿](INTEGRATION.md), 구현 규약은 각 항목의 근거 문서를 참고하세요. 과거 상세 문서의 테스트 개수·미검증 표시는 당시 시점의 기록입니다. 최초 소급 정리 당시 검증은235개였습니다. 이후 수정·재검증은 아래 후속 기록과 [CONTINUITY.md](CONTINUITY.md)에 별도로 기록합니다.

## 읽는 기준

- **구현/모의검증:** 코드·테스트 근거. 게임 물리와 모델 품질을 보장하지 않음.
- **실제 확인:** 명시한 fixture에서 실행·서버 관측 확인. 다른 환경으로 일반화하지 않음.
- **부분 해결/미해결:** 개선 근거와 남은 실패를 함께 기록. 제안은 구현 완료와 구분.
- 아래 날짜는 당시 커밋/관측을 묶은 일자입니다. 이번 소급 정리의 날짜와 구분합니다.
- 공개 문서의 근거 링크는 현재 규약/테스트입니다. 비공개 원본 커밋·실행·관리자 보고서 대응표는 별도 보존하며 키·서버 정보·원본 대화는 공개하지 않습니다.

### MC-001 · v1에서 API 기반 v2로 전환

**2026-10-15~16 · 설계·구현**

- 문제/배경: 기존 Python·NeoForge·Baritone 컨트롤러에서 모델 응답을 기다리는 플레이가 답답했고, 여러 봇을 API로 운영할 구조가 필요했다.
- 대응/결정: v1을 보존하고 TypeScript·Mineflayer v2를 추가했다. 생성 LLM의 계획, JEV의 선택, 로컬 스킬 실행을 분리했다.
- 결과·한계: v1의 소스는 남아 있으나 배포 JAR·완성된 Gradle 프로젝트는 포함하지 않는다. v2가 v1보다 빠르다는 비교실험은 하지 않았다.
- 근거: [관련 구현·검증](SPEC.md)
