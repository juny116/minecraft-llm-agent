# Minecraft LLM Agent

LLM이 목표·계획·대화를 만들고, JEV가 다음 행동을 고르며, Mineflayer가 실행하는 Minecraft Java 봇입니다. 현재 개발 대상은 **v2**입니다.

## 구조

```text
보이는 환경 + 내 상태 + 대화 + 기억
                 ↓
LLM: 근거 있는 목표 목록 / 중기 단계 / 대화 / 경험 가이드라인
                 ↓
JEV: 지금 실행할 행동 선택
                 ↓
로컬 실행기: 이동·채굴·전투·인벤토리 조작
                 ↓
선택 + 결과 + 상태 변화 → 기록 → 재계획·기억 갱신
```

- 화면·키보드 대신 Mineflayer의 상태·동작 API를 사용합니다.
- 시야와 가림을 기하학적으로 검사합니다. 전체 맵, 상대 인벤토리·체력은 모델에게 제공하지 않습니다.
- 제작법 입력은 서버에서 해당 봇에게 해금한 것만 제공합니다. LLM의 사전 지식까지 제한하지는 않습니다.
- 목표는 선택 사항입니다. `.env`가 아닌 실행 중 명령으로 지정·변경합니다.

## 액션 17종

| 범주 | 액션 | 역할 |
|---|---|---|
| 관찰·이동 | `look`, `move`, `follow`, `idle` | 둘러보기, 관측한 목적지 이동, 보이는 플레이어 접근, 대기 |
| 채집·건축 | `mine`, `pickup`, `place_block`, `place_table` | 블록 파괴·수거, 보이는 아이템 수거, 일반 블록·작업대 설치 |
| 제작·보관 | `craft`, `inspect_container`, `deposit`, `withdraw` | 제작, 상자·화로 관찰, 넣기·꺼내기 |
| 생존·전투 | `eat`, `equip`, `attack`, `flee` | 먹기, 장비 변경, 근접 전투, 도주 |
| 전달 | `give` | 보이는 플레이어 쪽으로 아이템 떨어뜨리기 |

화로는 기존 넣기·관찰·꺼내기를 재사용합니다. 대화는 별도 LLM 판단으로 처리합니다. `mine`은 **파괴 / 드롭 관측 / 실제 획득**을 구분하고, 시간 초과를 채굴 불가능으로 단정하지 않습니다. `give`도 상대 수령을 자동 확정하지 않습니다. [액션 규약](v2/docs/VISION_AND_ACTIONS.md)

## 기억 구조

| 기억 | 내용 | 재시작 후 |
|---|---|---|
| 경험·가이드라인 | 선택, 결과, 전후 상태, 근거·반례, 개정 이력 | 유지 |
| 사회적 기억 | 들은 말·자신의 발언·약속·행동 근거 | 유지 |
| 장소·보관함 | 직접 본 장소·열어 본 내용·관측 시각 | 유지하되 오래된 정보로 취급 |
| 자율 목표 | 이유·근거 ID·완료 기준·진행/보류 상태 | 복원 후 현재 관측으로 재검토 |
| 사용자 요청·중기 계획 | 현재 지시, 실행 단계와 최근 요약 | 자동 복원·재실행 안 함 |

고정 게임 설명, 사용자 요청, 봇이 세운 목표와 경험 기억을 별도 필드로 입력합니다. 진행 목표는 최대1개이며 보류 목표는 사유와 함께 남깁니다. 재접속 때 새 관측을 근거로 검토하기 전에는 일반 작업을 재개하지 않습니다. [목표 관리](v2/docs/GOALS.md)

각 봇의 기억은 분리됩니다. LLM이 경험을 검토해 가이드라인을 갱신하고, JEV는 현재 적 종류·내 장비·체력에 관련된 지침 최대4개를 받습니다. 정답이 아니라 수정 가능한 조언입니다. [메모리 상세](v2/docs/MEMORY-DESIGN.md)

## 시작하기

Node.js 22+, pnpm 11.25.0. GPU는 필요하지 않습니다.

```bash
cd v2
npx --yes pnpm@11.25.0 install --frozen-lockfile
npx --yes pnpm@11.25.0 typecheck
npx --yes pnpm@11.25.0 test
RUN_SECONDS=10 npx --yes pnpm@11.25.0 demo
```

`demo`는 서버·API·과금 없이 실행합니다. 실제 접속과 키 설정은 [사용법](v2/README.md)을 참고하세요.

## 검증 범위

후속15분 연속 기능검증을 정상 완료했습니다. 실제 작업 성공225건·이동 실패1건이었으며, 식사 지연과 후반 탐색 효율은 추가 보강 대상으로 분리했습니다. 최신 후속 수정과 실패한 접근은 [실행 지속성 검증](v2/docs/CONTINUITY.md)에 정리했습니다. 아래 과거 파일럿 수치와 구분해 읽어주세요.

현재278개 모의검증과 타입 검사를 통과했습니다. 최종2분 회귀 확인에서는 계획·기억·대화 오류0건, 이동/채굴 성공28건과 상호 발화3건을 확인했습니다. 실제 서버에서 주요 개별 기능과 두 봇의 상자 전달 → 제작 → 결과 발화를 짧게 검증했습니다. 지시된 기능검증이며 자발적인 협동이나 장기 생존을 입증하지 않습니다.

세부 목표 없이 두 봇이 5분 기능 파일럿을 완주했습니다. 실질 행동 성공50건·실패17건, 무동작 이동0건, 최저 관측 체력20이었습니다. 실패 후 재계획·원목/조약돌 획득·중간재/도구 제작·한국어 보고를 확인했습니다. 경험 기반 가이드라인도 저장됐습니다. 자연 스폰을 끈 단기 검증이며 본실험은 아직 진행하지 않았습니다. [검증과 한계](v2/docs/READINESS.md)

## 코드와 문서

`v2/src/` 구현 · `v2/test/` 모의검증 · `v2/scripts/` 명시적 기능검증 · `v2/docs/` 상세 규약. 기존 v1은 [LEGACY.md](LEGACY.md)에 보존합니다.

기능 변경 시 이 README의 액션·검증·TODO를 함께 갱신합니다. 키, 실제 서버 주소·계정·SSH 설정, 실행 로그·기억은 공개하지 않습니다. 푸시 전 나가는 커밋 이력도 확인합니다. [공개 전 점검](SECURITY.md)

API는 기본120초까지 기다립니다(thinking은 Luna 기준 none). 일시 오류는1회 재시도하고, 사용량 미확인 요청은 각 요청의 보수적 상한을 비용으로 차감합니다. 반복 과부하에는 제공자별2~30초 대기를 적용합니다. 응답 구조/사용량 누락3건 또는 인증/결제 오류에서는 중단하며 요청별 보수 비용·전체 금액 한도는 유지합니다. 늦은 결과의 상태 검증은 유지합니다.

현재 구현은 실행 중 JEV 감독, 독립 중기/장기 LLM, 의미 기반 메시지 분류·별명 기억, 사망 후 회수 의도 검토를 지원합니다. 통제된 실제 기능검증에서 행동·계획·대화 병렬 처리, 별명 응답, 리스폰·근거리 소지품 회수를 확인했습니다. [제어 루프](v2/docs/CONTROL_LOOP.md)

최근15분 통합 파일럿에서 장시간 정체·채굴 취소·작업대 반복·기억 검토 오류를 확인했습니다. 후속 수정은 작업 유지/전환, 봇별 정체 감지, 계획에 근거한 후보, 역할별 출력 예산과 요약, 작업대 지원면과 관찰을 보강했습니다. 실패한 수정 시도와 최신 재검증도 [실행 지속성 기록](v2/docs/CONTINUITY.md)에 보존합니다. 실행 시간과 유용한 성과를 구분하며 일반 야생 생존·자발적 협동 완성을 주장하지 않습니다.
